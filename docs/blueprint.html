1 큰 그림 — 두 개의 독립 축

시스템은 성격이 다른 두 축으로 나뉩니다. 혼동하지 않는 것이 핵심입니다. 현재 운영의 중심은 /ops/ (Supabase Hub) 이며, /app/ 은 단독 인쇄 도구로 병행 유지됩니다.

🖥️ /ops/ — 운영 Hub Supabase · 다중 페이지

로그인 기반 다중 페이지 운영 허브. 모든 부서가 같은 클라우드 DB를 공유합니다. 데이터 등록 → 방배정 → 인쇄물 → POS → 주방 → 정산까지 한 흐름.

  • 실시간 공유 · 어느 PC에서나 접속(키 내장)
  • 권한 체계(admin / manager / staff + 영역)
  • 일·한·영 3개 국어 + 후리가나 토글

🧾 /app/ — 인쇄 출력 시스템 단일 HTML · localStorage

엠클릭 엑셀을 직접 업로드해 9개 탭 인쇄물을 뽑는 단일 파일 도구. 서버 없이 브라우저 안에서 동작(localStorage 저장).

  • 네임택 · 항공커버 · 수배서 · 석식 · 정산 등
  • 인쇄 산출물은 모두 일본어 유지
  • /ops/ 로 4종 인쇄물 이식 완료 → 병행 사용

2 데이터 흐름 — 엠클릭에서 산출물까지 모든 섹션은 한 번 등록된 데이터를 읽어 동작

메리트투어 엠클릭(M-Click) 엑셀이 유일한 입력원입니다. STEP1에서 한 번 등록하면, 그룹코드·회원여부·항공정보가 계산되어 Supabase에 저장되고, 이후 모든 화면은 재계산 없이 읽어서 출력합니다.

엠클릭 엑셀예약리스트 · 일행별예약 · 그룹코드
→
STEP1 등록월 단위 동기화 · 그룹코드/회원 계산
→
Supabase DBbookings · passengers · guests · rooms …
→
전 섹션 출력방배정 · 인쇄물 · POS · 정산

입력 = 엠클릭 3종

  • 예약리스트
    행사(팀) 마스터. pax는 '예약' 컬럼 단독. 입도=팀 단위.
  • 일행별예약
    개인 명단 + 개인별 항공정보(출·귀국·항공사·PNR) + 고객등급.
  • 회원그룹코드 참조표
    그룹코드·회원 참조. 초기화해도 유지.

결합 키 = event_seq

행사 일련번호. 예약리스트(팀)와 일행별예약(개인)을 묶는 단일 키. 화면에 보이는 건 행사번호(event_no), 내부 결합·저장은 event_seq.

월 단위 동기화 — 업로드한 그 달(session_ym)에서 파일에 없는 팀은 확인을 거쳐 정리됩니다. 파일에 있는 팀은 id를 유지(배정 보존). 다른 달은 영향 없음.

3 섹션 지도 — 부서별 화면 구성 랜딩(ops/index.html) 기준

로그인 후 권한(영역)에 따라 보이는 카드가 달라집니다. 부서 단위로 묶여 있습니다.

객실/방배정(room) POS(pos) 정산(settle) 주방(kitchen) 메뉴(menu) 데이터(data)

② 통합 보드판전 직원 공통

4 핵심 워크플로우

🛏️ 방배정 자동화

  • 예약순(선착)
    event_seq 빠른 팀부터 처리.
  • 회원→디럭스 / 일반→예약종류
    고객등급 컬럼으로 회원·일반 판정. 각 풀 내 고층→저층.
  • 재실행 = 전체 재배치
    auto 배정만 지우고 처음부터 재분배. 수기·분할은 보호.
  • 정원·폐쇄 enforce
    하룻밤 단위 겹침 체크(다른 달 포함). 기간 폐쇄 방 제외.
취소 정책 — 취소건은 시스템에 등록하지 않음(현장 수기 ✕ 해제로 처리). 자동 회수 미사용.

🍽️ 주문 → 주방 → 정산

  • POS 주문
    팀 기본 · 개인 분할(특정 1인 / N분의1) 가능 → charges + folio.
  • 주방 티켓
    신규→접수→완료. 분할 무관 풀수량·팀단위.
  • folio 누적
    팀 folio + 개인 folio. 정산 화면에서 묶음 표시.
  • 체크아웃 명세서
    御請求書 출력(방번호 포함). 현장 추가요금.
정산 2종 분리 — ① 현지 정산표 = 메리트 B2B(선계약). ② 현장 정산 = 추가라운드·미니바 등. 혼동 금지.

5 핵심 도메인 개념

그룹코드2026년부터 3자리(영문2+가나1). 회원=사전배정, 일반=F풀(FAあ~). F 접두 = 비회원(팀 단위).
회원권 판정 2단계팀 = group_code F접두(비회원) / 개인 = 일행별예약 고객등급 컬럼(회원권 vs 일반고객). 등급(다이아·EWRC 등)은 회원권구분 컬럼으로 개인 보존.
방배정 단위개인 단위(4인 그룹이 트윈 2개로 쪼개짐). 디럭스급은 회원 우선, 일반은 예약종류(트윈·컴팩트).
숙소 구성야마나미리조트(골프텔·호텔·별장·돔하우스) · 쿠주힐즈 · 간지호텔 · 시즈노야도 료칸.
권한 체계역할 admin / manager / staff + 영역(step1·room·settle·pos·kitchen·menu·notes). 카드·민감테이블 RLS로 게이트. 계정은 admin이 초대 발급(자가가입 없음).
현지예약앱에서 직접 만들지 않음 → 엠클릭에 입력해 STEP1으로 정상 import(월 동기화 삭제 위험 방지).

6 기술 · 운영 메모

배포

GitHub Pages(main 루트 자동배포). 루트 → /ops/ 리다이렉트. 접근 게이트 없음(로그인은 ops 내부).

데이터베이스

Supabase(Postgres). RLS 권한 제어. publishable key 내장(공개 안전), secret key는 절대 미사용.

다국어

일본어 기본 + 한국어 + 영어 토글 + 후리가나(루비). data-i18n 사전 엔진.

개인정보

고객 PII 취급 내부도구 → 검색 색인 차단(noindex). 회원 마스터는 admin 전용. 처리방침 페이지 제공.

파일 규칙

다운로드 파일명 영문(회사 PC 한글 차단). 셀 내용은 한글·일본어 유지.

마이그레이션

Supabase SQL Editor 수동 실행(멱등). 번호순 01~34. 정산·방배정·POS 워크스트림 한 줄로 관리.
