# 현장 도입 물품 목록 (일본 조달 기준)

작성: 2026-08 · 기준 = `/ops/` 시스템이 실제로 요구하는 규격(코드 확정치)

이 문서는 **시스템을 현장에서 돌리는 데 필요한 물건만** 담는다.
규격(용지 크기·라벨 면수·스캐너 방식)은 추측이 아니라 **인쇄 CSS와 코드에서 그대로 뽑은 값**이다.
제품·가격은 2026-08 조사 시점 기준이며 변동한다 — **발주 전 링크에서 재확인**한다.

## 0. 먼저 확인할 것 (조달 전 4가지)

| 확인 | 왜 |
|---|---|
| **보유 프린터가 A3 세로·양면을 지원하는가** | 코스 배정표·夕食オーダー가 **A3 세로 전용**, 現地手配書가 **양면**이다. → **§1 체크리스트** |
| **보유 프린터가 레이저인가 잉크젯인가** | **네임택 라벨지 품번이 갈린다.** 잘못 사면 인쇄가 번지거나 롤러에 눌어붙는다. → **§2-1** |

## 1. 프린터 — **보유 중 (구매 불필요)** · 대응 여부만 점검

인쇄기는 이미 있으므로 **사지 않는다.** 대신 아래 3가지만 확인하면 된다.

### 1-1. 보유 프린터 점검 체크리스트

| # | 확인할 것 | 안 되면 |
|---|---|---|
| 1 | **A3 세로 인쇄** | 코스 배정표·夕食オーダー 2종만 영향 → **1-3 대안** 참조. 나머지 인쇄물은 전부 A4/A5라 문제없다 |
| 2 | **자동 양면 인쇄** | 現地手配書가 앞면(手配書)+뒷면(現地発生分 記入表)이다. 수동 양면(홀수→짝수 재급지)으로도 되지만 팀 수가 많으면 실수가 난다 |
| 3 | **레이저인가 잉크젯인가** | **라벨지 품번이 달라진다(§2-1).** 겸용 라벨지를 사면 어느 쪽이든 안전하다 |

### 1-3. A3가 안 될 때의 대안 (이미 만들어 둔 길)

A3를 못 뽑아도 **이 두 장은 다른 방법이 준비돼 있다.** 새로 사지 않아도 된다.

| 인쇄물 | 대안 |
|---|---|
| **夕食オーダー** | 화면의 **`⬇ 夕食オーダー 엑셀`** 버튼으로 날짜별 시트를 받아 **엑셀에서 A4로 나눠 인쇄**한다. 인쇄와 같은 데이터(제외·조기퇴실·묶음 반영)라 숫자가 어긋나지 않는다 |
| **코스 배정표** | ① 코스 입구 **모니터 화면**(`course.html?tv=1`)으로 대체 — 원래 손님 안내용이라 종이가 필요 없다. ② 종이가 꼭 필요하면 프린터 설정에서 **A3 → A4 축소(약 71%)** 로 뽑는다. 글씨가 작아지지만 팀이 적은 날은 읽을 만하다 |

> A3만을 위해 새 프린터를 사는 것은 권하지 않는다. **모니터(§6)를 먼저 놓고** 종이 수요가 실제로 남는지 한 달 지켜본 뒤 판단해도 늦지 않다.

### 2-2. 룸키 라벨 · 주문 QR 카드는 **라벨지가 아니다**

- **룸키 라벨**(`keyslip.html`): A4에 4열×8행(52.5×37.1mm)로 **점선(절취선)을 넣어** 인쇄하고 **잘라서 쓴다**. 이 치수의 규격 라벨지는 일반적이지 않아 **두꺼운 종이 + 재단** 방식으로 설계했다.
- **주문 QR 카드**(`qrcards.html`): 88×56mm(명함보다 약간 큼) 카드를 A4에 여러 장 인쇄 후 잘라 쓴다.

## 4. 결제 · 스캔 기기

### 4-1. QR 스캐너 — **설치처마다 기기가 다르다**

시스템은 **HID(키보드) 모드**로 동작한다. 스캔하면 어느 화면에 있든 그 팀이 바로 열린다.

**⚠ 반드시 「2차원(2D) 이미저」여야 한다. 1D 레이저 스캐너는 QR을 못 읽는다.**

| 필수 사양 | 값 |
|---|---|
| 코드 종류 | **QR 코드(2차원) 대응** |
| 접속 | **USB 유선 또는 Bluetooth · HID(키보드) 모드** — 드라이버 불필요 |
| 종단 문자 | **Enter(CR) 자동 부가** (기본값. 아니면 설정 바코드로 변경) |
| **화면 읽기** | **스마트폰·태블릿 액정에 뜬 QR 읽기 대응** — 손님이 폰으로 보여주는 경우가 있다 |

> **일본어 QR 대응은 우리에겐 불필요하다.** 우리 QR은 영숫자 토큰이다.
> 저가 모델(¥5,000~8,000)도 기술적으로는 읽는다 — 실무 차이는 **액정 화면 읽기·HID 기본 설정·일본어 매뉴얼·보증**에서 난다.

### 4-2. 카드 결제 단말 <span>(택시에서 본 그 방식)</span>

택시에서 보신 것은 **올인원 결제 단말** — 태블릿처럼 생긴 Android 기기에 **카드 리더 + 영수증 프린터 + 통신(4G)** 이 다 들어 있는 물건이다.
또는 **iPad/Android 태블릿 + 소형 카드 리더** 조합도 같은 그림으로 보인다.

#### ⚠ 먼저 알아야 할 것 — **우리 시스템과 자동 연동되지 않는다**

| | |
|---|---|
| **되는 것** | 우리 정산 화면이 **낼 금액을 계산**해 준다 → 그 금액을 단말에 입력해 카드를 긁는다 → 승인되면 우리 화면에 **[카드]로 기록**한다 |
| **안 되는 것** | 단말이 우리 시스템에 금액을 **자동으로 가져가거나 결과를 되돌려 주지 않는다.** 금액을 **두 번 입력**하게 된다 |
| 왜 | Airペイ는 Airレジ와, Square는 Square POS와만 붙는다. **우리 POS는 자체 제작**이라 연동 대상이 아니다 |

> 대안이 없지는 않지만(단말 제조사 SDK 연동) **개발·심사 비용이 결제 수수료 절감보다 훨씬 크다.** 지금 규모에선 권하지 않는다.
> 실무 권장 = **정산 화면 잔액을 보고 단말에 입력 → 승인 → 우리 화면에 [카드] 기록.** 단순하고 확실하다.

## 10. 확인이 필요한 항목 (발주 전 결정)

1. **보유 프린터 모델명** — A3·양면·레이저/잉크젯을 확정해야 라벨 품번과 §1-3 대안 필요 여부가 정해진다.
2. **태블릿 대수** — 청소팀·송영 인원 실제 편성에 맞춰 확정.
3. **航空カバー를 A5 용지로 뽑을지, A4에 2면 인쇄 후 자를지** — 후자면 A5 용지가 불필요하고 재단 수고가 는다.
4. **QR 카드를 코팅할지** — 단기 팀만이면 두꺼운 종이만으로도 버틴다(라미네이터 보류 가능).
5. **월 카드 매출액** — 카드 결제 단말은 이 숫자로 유불리가 갈린다. stera pack·Square 견적을 나란히 받는다.
6. **레스토랑 명패에 주문 QR을 넣을지** — 넣으면 무선 스캐너의 효과가 몇 배가 된다(코드 작업, §4-1).
