## 판단 근거

### 일반 카드리더기 vs 모바일 결제 — 지금은 차이가 작다

- 직접 가맹점 계약은 호텔·료칸 대형 기준 **2%대 후반**. 그런데 모바일도 중소사업자 할인으로
  **Square 2.5%**(연 캐시리스 3,000만엔 이하 등 조건)·**Airペイ 2.48%**(2024-12~)까지 내려와 **역전되는 경우도 있다.**
- **결정적인 건 우리 카드 매출이 아직 0**이라는 점이다. B2B 매출은 메리트투어 **송금**이라 카드가 아니고,
  카드로 받을 현장 추가요금은 `charges` **48건 ¥115,000**(2026-06~08) = 테스트 수준.

| 월 카드 매출 | 0.7%p 차이 | 연간 | 판단 |
|---|---|---|---|
| ¥500,000 | ¥3,500 | ¥42,000 | 단말 임대료 하나에 사라진다. 교섭 무의미 |
| ¥3,000,000 | ¥21,000 | ¥252,000 | 경계선 |
| ¥10,000,000 | ¥70,000 | ¥840,000 | **이때부터 직접계약 교섭이 값을 한다** |

- 직접계약의 숨은 비용 = 단말 임대료 월 ¥1,500~3,000 ×3대 · 회선비 · **카드 브랜드마다 개별 계약**(입금일·명세 제각각) · 심사 수 주.
- 모바일·올인원 = 월액 0 또는 첫해 무료 · 브랜드 일괄 · 입금 빠름 · **위약금·최소 계약기간이 사실상 없어 갈아타기 쉽다.**
- ⚠ 발주 전 **취급 브랜드 확인**(손님 대부분 한국인 → Visa·Master·JCB 필수, 銀聯 있으면 더 좋다).

### QR 스캐너 — 카운터용은 BCR-2D10GY가 맞다

60프레임/초 · 최소 3mil · **액정 화면 읽기 대응** · IP42 · 스탠드 오토센싱. ¥16,000에 이보다 나은 선택이 없다.
상위 기기(Zebra DS9308 ¥56,430 · DENSO QK30 ¥150,700)는 하루 수천 스캔용이라 **우리 볼륨엔 과잉**.
**일본어 QR 대응은 불필요**(우리 QR은 영숫자 토큰) — 실무 차이는 액정 읽기·HID 기본 설정·매뉴얼·보증에서 난다.

### 레스토랑 — 기기보다 명패 QR이 먼저

지금은 **손님이 QR 카드를 꺼내야** 스캔이 된다. **명패에 팀 주문 QR을 병기**하면 직원이 명패만 스캔하면 된다.
**이 작업은 리더기를 실제로 사는 시점에 함께 넣는다**(Min 결정 2026-08) — 스캔할 기기가 없는데 QR만 올려두면 헷갈린다.
그러니 순서 = ① 태블릿 카메라(¥0, 이미 POS에 있음) 한 달 → ② 느리면 무선 스캐너 **BCR-BT2D4BK** ¥21,000 **＋ 명패 QR 같이** → ③ 핸디터미널 ¥50,000~는 과잉.

### 주방 화면은 레스토랑 태블릿과 한 짝이다 (2026-08 검수에서 추가)

POS로 주문을 넣으면 `kitchen_tickets` 가 생기고 **주방이 `kitchen.html` 에서 [접수]→[완료]를 눌러야** 프론트(`pos.html` 주문 현황)가 진행 상황을 본다.
주방에 화면이 없으면 **주문이 주방에 도달하지 않는다**. 24~27인치 모니터＋스틱PC 벽걸이(¥45,000, 남는 모니터가 있으면 스틱PC만 ¥25,000).
조리 중 손이 젖고 멀리서 봐야 하므로 태블릿보다 벽걸이가 맞다. 바(bar)를 따로 두면 `kitchen.html?view=front` 로 같은 화면을 쓰거나 화면을 하나 더 둔다.

### 주문·스캔하는 태블릿은 전부 셀룰러(SIM) 모델로 (Min 2026-08)

처음엔 송영 2대만 SIM으로 잡았는데, **가장 흔한 장애가 AP 고장이 아니라 회선·ISP 장애**다.
그때 Wi-Fi 전용 모델은 「연결은 됐는데 인터넷이 없는」 AP를 붙잡고 그대로 멈춘다 — 사람이 알아채고 손을 써야 한다.
셀룰러 모델은 **스스로 회선으로 넘어간다.** 돈이 오가는 주문·결제 기기라 대당 +¥12,000 · 월 ¥2,000의 값을 한다.

→ **SIM 4개** = 송영 2 + 레스토랑 1 + 골프샵 1. 주방 화면은 벽걸이라 **유선 LAN**이 가장 안정적이다.

### 태블릿 기종 = 샤프 SH-T04C (2026-08 확정)

¥61,800/대 · 10.1형 WUXGA · Android 14 · Snapdragon 695 5G · 4GB/64GB · 481g · 6680mAh · **eSIM** ·
**IPX5/8 방수 ＋ IP6X 방진**.

- **방수가 기종을 결정했다.** 레스토랑 카운터는 음료가 튀고 골프샵은 손이 젖는다. 이 가격대에서 방수 5G 태블릿은 사실상 이것뿐.
- **iPad는 뺐다** — Wi-Fi+Cellular 가 2026-06 인상 후 약 ¥100,000이고 **방수가 없다**. 오래 쓰는 건 장점이나 이 용도엔 맞지 않는다.
- **4대 같은 기종으로 통일** — 충전기·케이스·설정·매뉴얼·예비기를 공유하고, 한 대가 고장 나면 서로 대체한다. 기종이 섞이면 현장이 헷갈린다.
- ⚠ **eSIM 전용**(물리 SIM 슬롯 없음) — 회선 계약 전 eSIM 지원 여부를 확인한다.
- 4GB RAM 은 웹앱 한 화면엔 충분하다. 탭을 여러 개 띄우지 않는다.

### 태블릿 — 처음엔 4대

**동시에 다른 장소에서 쓰는 것만** 셌다: 레스토랑 POS 1 · 골프샵 1 · 송영 2(기사용·미팅/샌딩용). 청소·손님확인은 실제 편성을 보고 증설.

### A3 — 확인 완료(백업으로만)

TASKalfa 3554ci가 A3(手差し 최대 SRA3)를 지원하므로 아래 대안은 **쓸 일이 없다.** 기기 고장 등 비상용으로만 남긴다.

### A3가 안 되면(백업)

**夕食オーダー** = 화면의 「⬇ 夕食オーダー 엑셀」로 받아 A4로 나눠 인쇄(인쇄와 같은 데이터).
**코스 배정표** = 입구 모니터(`course.html?tv=1`)로 대체하거나 A4 71% 축소.
**A3만을 위해 프린터를 새로 사지 않는다.**

## 운영 규칙 (2026-08 검수에서 확정)

### 카드 단말은 시스템과 연동하지 않는다 (Min 결정)
단말에 금액을 치고 정산 화면에 또 친다 = **이중 입력**. 오타가 나면 장부와 입금이 어긋나고 발견은 한 달 뒤다.
→ **단말 영수증을 청구서에 붙여 보관**하고, 마감 때 단말 일계표와 정산 화면 합계를 맞춘다.
자동 연동은 API 제공 단말(수만 엔~·월 임대)이라 카드 매출이 붙은 뒤에 본다.

### 인터넷이 끊기면
Supabase 온라인 전용이라 **주문·저장이 실패한다**. 전 ops 화면 맨 위에 **빨간 띠**가 뜬다.
- 담아둔 **장바구니는 사라지지 않는다**(태블릿을 꺼도·새로고침해도·전송 실패해도 유지) → 연결되면 [주문 전송]만 다시.
- 길어지면 **종이에 적고 나중에 입력**한다.
- 예방 = 메시 AP(2단계) + **주문·스캔 태블릿은 전부 셀룰러 모델**(레스토랑·골프샵·송영). 주방 화면은 유선 LAN.

### 워크인(예약 없는 손님)
POS **[＋ 워크인]** → 이름(선택)·인원 → 전표. 주문·주방 티켓은 예약 팀과 같고 **계산만 그 자리에서**(현금/카드 → 받고 마감).
예약 데이터(bookings)에는 넣지 않는다 — 엠클릭 재등록 때 지워지지 않게. `walkins` 테이블·전용 번호대(9,900,001+).
