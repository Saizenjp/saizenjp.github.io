# ③ 現地手配書 (현장 수배서) — 기술명세

SaiZen Yamanami 운영 통합 시스템(`app/index.html`)의 ③ 現地手配書 탭 기술 문서.
작성일: 2026-06-05 (v14.3 갱신: 2026-06-17) / 적용 버전: v6 (앱 v14.3 — 골프 단순화·特記事項 비고 3컬럼·미리보기 라벨 반영)

> **Hub 마이그레이션 참고 (v14.4):** 이 문서는 `/app/` 단일 HTML 탭 기준이다. 출력물 통합 마이그레이션에서 현지수배서는 추후 **Hub(/ops/) 카드로 이식** 예정이며, 그때는 Supabase를 읽어 본 문서의 인쇄 로직을 재사용한다. 이식에 필요한 **인별 항공 필드(출발지·항공사·PNR·시각 4종 등)·bookings 현지/기타 비고는 이미 Supabase에 적재**되어 있다(마이그레이션 `07_passenger_air`, STEP1 등록). 우선순위상 네임택+항공커버(1c) 이후 순번.

## 1. 개요

엠클릭에서 행사별로 랜드수배서를 건건이 열어 다운로드하던 작업을 대체한다. 업로드된 월 세션 데이터 전체에서 행사별 수배서를 일괄 생성하며, **1행사 = 정확히 2페이지** 구조다.

- **앞면**: 手配書 — 행사 개요 · 항공 · 숙박 · 고객명단 · ゴルフ場(코스명) · 特記事項
- **뒷면**: 現地発生分 記入表 — 현지 발생분(라운딩 추가·EV카트·식음·연박·송영·기타) 수기 기입 양식
- 출력: HTML 인쇄 미리보기(기본) + xlsx 다운로드 병행
- 양면 인쇄(긴 가장자리 제본) 선택 시 앞·뒤가 자동 정렬됨 (모든 행사가 짝수 2페이지이므로 어긋나지 않음)

엠클릭 랜드수배서의 모든 항목은 입력 2파일(예약리스트·일행별예약)로 100% 재구성된다. (v14.0 — 기존 4파일에서 현지도착·그룹코드 의존 제거. 항공 시각·영문명·APIS를 일행별예약이 모두 포함)

## 3. 데이터 소스 · 연계

수집 함수 `collectDispatchData()`: `processed` 중 `accom`이 있는 행사만, 출발일 → 대표자명 순 정렬. 결합 키는 `eventSeq`.

| 출력 항목 | 소스 |
|---|---|
| 행사 개요 (출발·도착일, 박수, 인원, 대표자, 상품명) | 예약리스트 (`processed` / `rec.raw`) |
| 特記事項 (비고 3컬럼) | 예약리스트 `비고`·`현지 비고`·`기타 비고` + 수기 `【現地メモ】` (5절 참조) |
| 회원권구분 · 행사번호 | 예약리스트 (현지도착 폐지) |
| タグコード | `buildTagCodeMap()` → `makeTagCodeSafe(...)` (paxIdx 0 = 대표 기준) |
| 고객명단 (한글명·영문성·영문이름·성별·생년월일·여권번호·휴대번호·代表 표시) | 일행별예약 (`passengers`) |
| 항공편명 · 항공사 | 일행별예약 (대표 승객) |
| 항공 시각 (往路 한국출발·현지도착 / 復路 현지출발·한국도착) | 일행별예약 (대표 승객): `한국출발` / `현지도착` / `현지출발` / `한국도착`. 현지도착 파일 폐지 → `arrivalMap`은 레거시 폴백만 유지 |
| 출발지 ICN/PUS 판정 | 일행별 개인 출발지 우선(예약리스트 → 항공편 추정 순). `origin`에 '부산' 포함 또는 출발편 `ZE` 시작 → PUS |
| 숙박 시설·룸타입 | `parseProduct` 결과 + 일본어 표기 변환 |
| ゴルフ場 (코스명만) | `dispatchCourseSummary(d)` — `dispatchGolfRows()` 결과의 코스 중복 제거. **일자별 라운드 일정은 미표기**(v14.1, 4절 참조) |

## 4. 라운딩 일정 규칙 — `dispatchGolfRows(rec, isPUS)`

> **(v14.1) 수배서 앞면에는 일자별 라운드 일정을 더 이상 표기하지 않는다.** 宿泊情報처럼 **ゴルフ場(코스명)만 한 줄**로 출력한다(`dispatchCourseSummary`가 아래 산출 결과에서 코스 중복 제거). 일자별 티오프·홀수 등 상세는 향후 별도 골프 수배서로 분리 예정이며, `dispatchGolfRows()`는 코스 목록 산출용으로 유지된다.

지침의 골프 라운딩 배정 규칙을 날짜 경계(출발일=입국일, 도착일=귀국일)에 맞춰 자체 구현했다. 기존 `getGolfInfo()`를 호출하지 않는다 (해당 함수의 귀국일 경계가 도착일−1로 정의되어 있어 수배서 용도와 어긋남).

| 구분 | 입국일 (dep) | 중간일 | 귀국일 (arr) |
|---|---|---|---|
| 인천(ICN) | やまなみCC 18H | 18H (+평일 9H서비스) | 라운딩 없음 |
| 부산(PUS) | 라운딩 없음 | 18H (+평일 9H서비스) | やまなみCC 9H |

- 간지호텔 중간일: 평일·비공휴일 → 九重高原CC / 주말·공휴일 → やまなみCC (`isNonWorkday`·`isJpHoliday` 사용)
- 중간일 備考: 평일 `+9Hサービス対象`, 주말 `週末`, 공휴일 `祝日`
- 검증: 엠클릭 샘플(ICN 4박5일 06-07→06-11)과 라운딩 일자 정확히 일치 (06-07~06-10, 4라운드)

## 5. 수기 입력 — 📝 입력 모달

목록의 「📝 입력」 버튼 → `openDispatchInputModal(seq)` → 저장 시 `saveDispatchInput(seq)`. 행별 「🖨 미리보기」 버튼(v14.2: 아이콘 단독 → 라벨)은 `printDispatch(seq)` 호출.

### 저장 구조

```js
manualData['dispatch_{eventSeq}'] = {
  teeoff: { 'YYYY-MM-DD': 'HH:MM', ... },  // (v14.1) 모달 입력 제거 — 기존 값 보존만, 신규 입력 없음
  roomCnt: '3室',                           // 방수 덮어쓰기 (공란이면 자동 계산)
  memo: '레이트체크아웃'                     // 現地メモ
}
```

- 기존 `manualData` → `saveManual()` 체계 그대로 사용 → **월별 세션 localStorage** (`merit_session_manual_{YYYY-MM}`)에 저장. 세션 전환·재접속 후에도 해당 월 데이터에 유지된다.
- 세 항목이 모두 비면 키 자체를 삭제해 저장소를 오염시키지 않는다.

### 항목별 우선순위

| 항목 | 우선순위 |
|---|---|
| 部屋数 | 수배서 입력 > 자동 계산 — 룸타입에 '트윈' 포함 시 `ceil(pax/2) + '室 (2人1室)'`, 그 외 `'-'` |
| 特記事項 | (v14.1) 예약리스트 **비고 3컬럼**(`현지 비고` → `비고` → `기타 비고`) + 수기 `【現地メモ】` 순. **현지 비고는 전체 굵게**, `비고`는 현지 중요 키워드(체크인·레이트·알러지·픽업·휠체어·룸업·캐디·VIP·요청 등) 포함 **구절만 굵게**, `기타 비고`는 일반. HTML `<b>` / Excel richText. 빈 칸 자동 생략 |

> (v14.1) 모달에서 ティーアップ 입력 제거 — `部屋数`·`現地メモ`만 입력. 골프 티오프는 ⑦ 골프배정표에서 관리.

- 입력이 있는 행사는 목록 대표자명 옆 ✏️ 배지로 표시 (`hasManual` 플래그)

## 7. 필터 · 검색

화면 상태 변수 3종 (localStorage 비저장, 새로고침 시 초기화):

```js
dispatchSearchQ      // 검색어 (소문자 비교)
dispatchAccomFilter  // Set — 빈 Set = 전체
dispatchDateFilter   // Set — 출발일 기준, 빈 Set = 전체
```

- **검색**: 대표자명 · 행사번호 · 태그코드 · eventSeq 부분 일치 (대소문자 무관)
- **시설 칩**: 전체 / YAMANAMI / KUJU HILLS / GUERNSEY / SHIZUNOYADO — 복수 선택 가능
- **출발일 칩**: 세션 데이터에서 자동 생성
- 판정 함수 `dispatchPass(d)` — **핵심 동작: 「전체 일괄 인쇄」와 Excel 다운로드는 필터·검색 통과분(화면 표시분)만 대상**. 카운트는 "N건 표시 / 전체 M건"으로 표기. 행별 개별 인쇄(🖨)는 필터와 무관하게 해당 행사만 출력.

## 8. HTML 인쇄 — `printDispatch(seq?)`

- 인자 없으면 표시분 전체, `seq` 지정 시 단건. `window.open` 새 창에 미리보기 + 인쇄 버튼.
- 페이지 규격: `.hp-page` 폭 210mm, 인쇄 시 높이 296mm 고정 + `overflow:hidden` + `page-break-after:always`, `@page { size:A4 portrait; margin:0 }` — 모든 시트가 정확히 2페이지가 되도록 강제해 양면 정합을 보장.
- 고객명단 폰트 자동 축소: 인원 11~16명 `g-sm`(8.3pt), 17명 이상 `g-xs`(7.4pt).
- 명단 미등록 행사는 "名簿未登録 — 代表: ○○○ 計N名" 폴백 행 출력.
- 뒷면 기입표: 12행(행높이 12.5mm) × 日付/区分/内容/数量/単価/金額/担当, 区分 셀에 ①~⑥ 프리프린트(현장에서 ○ 표시), 合計 행, 확인란(記入者(現場)/確認者/記入日).
- 툴바에 총 페이지 수, 마스킹 상태, 양면 인쇄(긴 가장자리 제본) 안내 표시.

## 9. Excel 다운로드 — `downloadDispatchXlsx()`

- ExcelJS 4.3.0 사용, 저장은 공통 `xlSave()`.
- 구조: `🖨 인쇄 안내` 시트(전체 통합 문서 인쇄 + 양면 설정 안내) + **행사별 1시트**.
- 시트명: `MM-DD 대표자명` (금지문자 제거, 27자 절단, 중복 시 `(2)` 부여, Excel 31자 제한 준수).
- 앞면 구획 작성 후 `ws.getRow(r).addPageBreak()` → 뒷면 기입표(12행, 행높이 34) — 시트당 인쇄 2페이지.
- 페이지 설정 `A4P`: A4 세로, `fitToWidth:1, fitToHeight:0`.
- 열 폭 10열 고정(`COLW`, 고객 표 기준), 다른 표는 셀 병합으로 대응. 마스킹 ON 시 고객 표는 8열(備考 H:J 병합).
- 파일명: `現地手配書_{YYYY-MM-DD}.xlsx` / 마스킹 OFF 시 `現地手配書_全体表記_{YYYY-MM-DD}.xlsx`.

시설 일본어 표기: 야마나미리조트 → 阿蘇やまなみリゾート / 쿠주힐즈 → 久住ヒルズ / 간지호텔 → 間地ホテル / 시즈노야도 료칸 → シズノヤド旅館

## 11. 제약 · 주의사항

- (v14.0 해소) 復路 한국 도착시각은 일행별예약 `한국도착` 컬럼으로 출력된다. 일행별 명단이 없는 행사(현지예약 등)만 시각이 비며, 이는 운영 대상에서 제외된다.
- (v14.1) 앞면 골프는 코스명만 표기 → 특기사항 공간 확대(메모 박스 15→30mm). 일자별 라운드 상세는 ⑦ 골프배정표 또는 향후 별도 골프 수배서 활용.
- 部屋数 자동 계산은 트윈 계열 룸타입에만 적용되며, 그 외(돔하우스·별장·료칸 등)는 `-` → 필요 시 입력 모달에서 수동 기재.
- 초장기 체류 + 대인원 행사는 앞면이 1페이지를 넘칠 수 있으나, 양면 정합 유지를 위해 의도적으로 clip 처리된다(폰트 자동 축소로 통상 케이스는 모두 수용).
- 마스킹 OFF 출력물은 여권번호·전화번호가 포함되므로 취급에 주의한다.
- 필터·검색 상태는 저장되지 않는다(새로고침 시 전체 표시로 초기화). 마스킹·수기 입력은 저장된다.
