# 현장 정산 시스템 — 설계명세 (docs/04)

> Claude Code가 이 시스템을 구현할 때 따르는 설계 문서. **코드가 정답이며, 이 문서는 의도·규칙을 정의한다.**
> 모든 작업은 `/ops/` Hub(Supabase, 다중 페이지) 위에서 진행한다. `/app/`(localStorage)와 무관.
> 구현 현황: **Phase 1 완료** — `ops/hub/sql/09_settlement_core.sql` · `ops/hub/settle.html` · 랜딩 카드(ix_c5).

---

## 0. 목적 / 범위
- 야마나미 현장에서 발생하는 **손님 추가요금**(연회장·레스토랑·추가 라운딩·골프샵·룸 업그레이드 등)을 한 손님(체류)의 **정산 계정으로 모아 결제·합산**한다.
- 산출물: **손님용 체크아웃 명세서(御請求書)** + **내부 매출 요약**. 둘 다 ExcelJS 4.3.0(파일명 영문, 내용 일/한).
- ⚠ **B2B 정산(⑤ 現地精算表, 메리트투어↔사이젠 선계약)과는 완전히 별개 시스템**이다. 이 레이어에 B2B 금액(`bookings.sales_amount` 등)을 섞지 않는다.

## 1. 핵심 원칙
- **folio(정산 계정) 중심.** 체류(행사)마다 folio 1개가 열린다.
- **charges(통합 청구 원장)가 연동 지점.** 연회장·레스토랑·골프·골프샵·방 등 모든 시스템이 charges에 한 줄씩 적재한다.
- **잔액 = Σ(charges.amount+tax+service_charge) − Σ payments.** (뷰 `v_folio_balance`에서 계산, DB에 중복 저장하지 않음)
- **상세는 각 서브시스템 테이블, 합산은 charges.** (예: 레스토랑 주문 상세는 restaurant_orders, 확정 시 charges에 '식음' 1행 요약 적재)
- 통화는 **엔(JPY) 정수**로 다룬다(소수점 없음).
- 취소는 **삭제 대신 `voided` 무효화**(금전 감사 추적).

## 2. 데이터 모델

### Phase 1 (코어 — `09_settlement_core.sql`) ✅ 구현됨
- **folios**: `id`(uuid PK), `event_seq`(→bookings), `subject`('team'|'member'), `member_id`(→guest_members, nullable), `status`('open'|'closed'|'settled'), `session_ym`, `opened_at`, `closed_at`, `note`, `created_by`
- **charges**: `id`, `folio_id`(→folios, cascade), `event_seq`, `category`(5종 CHECK), `source`, `description`, `qty`, `unit_price`, `amount`(세전 소계), `tax`(소비세 별도), `service_charge`(현 0), `member_id`, `source_ref`, `charged_at`, `created_by`, `note`, `voided`
- **payments**: `id`, `folio_id`(→folios, cascade), `method`('현금'|'카드' CHECK), `amount`, `paid_at`, `received_by`, `note`, `voided`
- **뷰**: `v_folio_balance`(folio별 청구합계·결제·잔액) · `v_settlement_by_category`(카테고리·월별 매출요약)

### Phase 2 (간이 POS — `10_pos_menu.sql`) ✅ 구현됨
- **menu_items**: `id`, `code`(번호/기호), `name_ja`·`name_ko`, `category`(5종), `venue`(restaurant/banquet/proshop/etc → charges.source), `unit_price`(세전), `sort_order`, `active`
- 페이지: `ops/hub/pos.html`(태블릿 주문 입력) — **오늘 체크인 팀 목록 탭 → 메뉴 버튼 그리드 탭 → 카트 → 전송**. 전송 시 그 팀의 열린 folio(없으면 생성)에 charges 직접 적재.
- ⚠ 외부 POS 연동 없음(현장 POS 미보유). v1은 **`restaurant_orders` 중간 테이블 생략** — 카트→전송으로 charges 직접 적재. 주방 티켓·다단말 동시편집이 필요해지면 그때 `11_`로 도입.

### Phase 3 (주방 화면 KDS — `11_kitchen_tickets.sql`) ✅ 구현됨
- **menu_items.station** 추가: `kitchen`(조리→티켓) · `bar`(드링크바 즉석, 티켓 없음) · `none`(골프샵 등). ⚠ station은 category로 자동판별 불가(같은 '식음'에 生ビール=bar·定食=kitchen) → 항목별 지정 필요.
- **kitchen_tickets**: `id`, `folio_id`, `event_seq`, `team_tag`, `station`, `item_name`, `qty`, `note`, `status`('new'|'done'), `created_by`, `created_at`, `done_at`
- 페이지: `ops/hub/kitchen.html`(주방 태블릿) — status=new 라이브 큐, **자동 폴링 7초**, [완료]→done. 경과시간 색(10분 주의·20분 지연). station 필터(주방/드링크바/전체).
- 흐름: POS 전송 = charges 적재(돈) + **주방행(station=kitchen) 항목만 티켓 발행**. 카트→전송이 곧 확인 단계이므로 **2차 확인 없이** 주방 즉시 표시(Min 확정). 드링크는 바에서 직접 제조(티켓 없음).
- charges(돈 장부)와 kitchen_tickets(조리 큐)는 분리 — 완료해도 charges는 유지.

### 메뉴 관리 (Hub) ✅ 구현됨
- 페이지: `ops/hub/menu.html` — menu_items CRUD(단건 추가·행별 저장/삭제·활성 토글) + **일괄 붙여넣기**(`일본어명, 한국어명, 구분, 장소, station, 단가, code` CSV/탭, 메뉴판 한 번에 입력). venue별 그룹 표시.
- 메뉴 삭제해도 과거 charges는 발생시점 단가를 스냅샷 저장 → 안전.

### Phase 4+ (추후)
- **restaurant_orders / banquet_events**: 본격 오더 탭(개설→수정), KDS 실시간(Supabase Realtime) 등 필요 시.

### folio 라이프사이클
`open`(체크인 시 생성) → 체류 중 charges/payments 누적 → 체크아웃 시 명세서 출력 → `closed` → 결제 완료 시 `settled`. (settle.html에서 마감↔재개 토글 가능)

## 3. 출력
- **손님용 체크아웃 명세서(御請求書)**: folio별 charges 항목 나열 + 소계/소비세/합계 + 결제/잔액.
- **내부 매출 요약**: category·월별 집계(`v_settlement_by_category`).
- 인쇄 문서는 **네이비/모노톤 팔레트**(`#1A2540`/`#1A4D8F`) — 화면 올리브 팔레트와 독립.

## 4. 기존 스키마 연결
- `folios.event_seq` = `bookings.event_seq`. 개인 정산 시 `folios.member_id` = `guest_members.id`.
- 회원 등급 필요 시 기존 `member_codes`(이름+생년 매칭) 재사용.

## 5. Hub 규약 (준수함)
- Supabase 연결: `room.html` 패턴 재사용(supabase-js@2 CDN, creds localStorage `saizen_sb_url`/`saizen_sb_key`).
- i18n: `saizen-ops.js` 사전에 `st_*` 키 추가(ja/ko/en). **t()는 미존재 키를 키 문자열로 반환** → 키 존재 확인 완료.
- 색: **CSS 변수만**, 라이트 전용.
- `saizen-ops.js/css` 변경 → 모든 Hub 페이지 `?v=` 캐시 올림(**14.6 → 14.7**).
- SQL: Supabase Dashboard SQL Editor에서 **수동 실행**, 번호순(09), **멱등**.
- 랜딩(`ops/index.html`) ix_c5 카드를 '현장 정산' 활성 링크로 전환(기존 '정산·대시보드' 준비중 카드 대체).

## 6. 보안 (금전 데이터 — 중요)
- 이건 **돈 데이터**다. `09`의 anon 전체허용 RLS 정책은 **개발 단계용 임시**다.
- **운영 투입 전 반드시 접근 제한 강화**(담당자 인증/역할 분리). 이 강화 작업은 후속 과제로 남는다.

## 7. 단계 (권장 순서)
1. **코어**: folios + charges + payments + 명세서/매출요약 출력. ✅ **완료(Phase 1)**
2. **간이 POS**: menu_items + 태블릿 주문 화면(pos.html) → charges 직접 적재. ✅ **완료(Phase 2)**
   - 팀 식별 = 오늘 체크인 목록 탭 · 메뉴 = 버튼 그리드 탭 · 확정 = 카트 후 전송 (Min 확정).
3. **주방 화면(KDS)**: kitchen_tickets + menu station 라우팅 + kitchen.html 라이브 큐. ✅ **완료(Phase 3)**
   - 전송=주방 즉시 표시(2차 확인 없음) · 라이브 큐+완료버튼 · 자동 폴링 (Min 확정).
4. (필요 시) 골프·룸 업그레이드 charges 연결, 메뉴 관리 화면, KDS 실시간.

## 8. ✅ Min 확정값 (2026-06)
설계 비즈니스 값은 Min님이 확정함. 명세서·세금 계산·드롭다운에 반영 완료.
- **결제수단**: **현금 / 카드** (`payments.method` CHECK).
- **세금·봉사료**: **소비세 10% 별도**(세전 단가 입력 → `tax = round(amount*0.10)`), **봉사료 없음**(`service_charge` 항상 0).
- **통화**: **엔(JPY) 고정**, 정수.
- **folio 단위**: **팀(행사) 단위 기본 + 개인(member) 허용**.
- **카테고리(고정 5종)**: **라운딩 · 식음 · 숙박 · 골프샵 · 기타**.
- **명세서 머리글**: `御請求書 / アソ ヤマナミリゾート ／ 株式会社SaiZen` (상세 회사정보·인감은 후속 확정 시 보강).
