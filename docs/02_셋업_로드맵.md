# 프로젝트 셋업 가이드 & 향후 진행 방향

사이님(Min)이 두 운영 관리 시스템을 프로젝트로 옮겨 진행하기 위한 종합 안내서.

> **저장소는 3개, 프로젝트는 2개로 나눈다.**
> - MERITTOUR 프로젝트 ← `merittour-tools`(사내 도구함, 주력) + `merittour.github.io`(고객 안내 페이지, 설계 참고용)
> - SaiZen 프로젝트 ← `saizenjp.github.io`(현장 운영 자동화 앱)
>
> 메리트투어 쪽 저장소 2개를 한 프로젝트에 묶는 이유는, 둘 다 한국 본사의 업무이고(도구함=직원용, 고객페이지=고객 안내용) 같은 데이터·표준을 공유하기 때문이다. 사이젠은 일본 현장·일본어·현장 산출물이라 성격이 달라 분리한다.

## 1부. 프로젝트 만들고 셋업하기

### 1단계 — 프로젝트 2개 생성
Claude 좌측 사이드바에서 "프로젝트" → "새 프로젝트"로 두 개를 만든다.
- **MERITTOUR 운영 관리 시스템**
- **SaiZen 운영 관리 시스템**

### 2단계 — 각 프로젝트에 지침(커스텀 인스트럭션) 넣기
프로젝트 설정의 "지침(Instructions)" 칸에 아래 문서 내용을 붙여넣는다.
- MERITTOUR 프로젝트 ← `메리트투어_프로젝트_지침.md` 내용
- SaiZen 프로젝트 ← `사이젠_프로젝트_지침.md` 내용

### 3단계 — 각 프로젝트에 지식(파일) 올리기
프로젝트의 "지식(Project knowledge)" 영역에 다음을 업로드한다.

**MERITTOUR 프로젝트 지식:**
- `merittour-tools-main.zip` (사내 도구함 저장소 전체 — dashboard 포함 최신본)
- `merittour.github.io-main.zip` (고객 안내 페이지 저장소 — about 등, 설계 참고용)
- `dashboard_기술명세.md` (현재 dashboard 구조 설명)
- 엠클릭 샘플 4종: 예약리스트, 일행별예약, 현지도착, APIS 정보
- 호텔 블록 샘플 2종: 호텔블록및요금조회.xlsx, 월별호텔수배현황.xls
- 알리고 PNR 안내 템플릿 xlsx
- merit-logo.svg (로고)

**SaiZen 프로젝트 지식:**
- `saizenjp.github.io-main.zip` (사이젠 저장소 전체 — app/index.html + assets 로고 포함)
- 또는 개별로: `saizen-app-latest.html`(자동화 앱 본체) + 로고 3종(logo-saizen-*.svg)
- 엠클릭 샘플: 예약리스트(예약현황 탭)·일행별예약(탑승자정보 탭) — 2파일 체계. 그룹코드 참조테이블(선택·한번 등록 시 유지). ※ 현지도착 파일 폐지. 각 파일 500행 분할 시 여러 개 업로드(자동 병합)

> 팁: 저장소는 zip 통째로 올리는 게 가장 확실하다. GitHub의 Code → Download ZIP으로 받아 올리면 Claude가 전체 구조를 본다. (Claude는 public 저장소라도 raw/API 주소를 임의로 직접 호출하지는 못하므로, zip 업로드가 가장 안정적이다.)

### 4단계 — 작업 이어가기
프로젝트 안에서 새 대화를 시작하면 지침과 지식이 자동 적용된다. 첫 대화에서 "dashboard 이어서 작업하자" 또는 "사이젠 v14 작업하자"처럼 시작하면 된다.

> 참고: 지금까지의 채팅 메모리는 프로젝트 밖에 쌓여 있어 프로젝트 대화에서 곧바로 끌어 쓰진 못한다. 하지만 위 지침·지식 문서에 핵심 맥락을 다 담았으므로 작업에 지장은 없다. 과거 대화 내용이 필요하면 "예전에 ~했던 것 찾아줘"라고 하면 검색할 수 있다.

### 다음 단계 (기존 로드맵 순서)
1. **GitHub Pages 배포 마무리** — dashboard 업로드 완료. Pages 활성화 상태 최종 확인.
2. **리조트 마스터 실값 입력** — 월별 환율, 항공요금(월×노선×박수), 그린피·식사·회원관리비 단가를 실제 값으로 채운다. 이게 채워져야 요금 검증이 정확해진다.
3. **엠클릭 API 연동 검토** — 엠클릭시스템 CEO와 친분이 있으므로 API 제공을 요청한다. 연동되면 파일 업로드 없이 자동으로 데이터를 끌어오고, 발권 완료 여부도 자동 판별 가능.
4. **클라우드 서버 구축** (월 1~3만원) — 자동 스케줄 발송(출국 D-7 알림톡 자동 발송 등).
5. **장기: Firebase 연동, SaaS 확장** — 다른 여행사도 쓸 수 있는 형태로 확장.

### 검토해볼 만한 추가 기능
- 호텔블록 재고 현황을 dashboard ⑩ 섹션으로 추가(블록 파일 업로드 + 블록 대비 잔여). 현재는 별도 호텔블록 대시보드로 존재.
- 미수금 안내·PNR 안내 등 섹션별 "발송 대상 추출" 고도화.
- 보험 정보 섹션에 보험코드매칭(insurance 도구) 결과 연동.

## 4부. 두 시스템의 관계 (중요)

메리트투어(한국 본사)가 한국 고객 예약을 받아 → 사이젠(일본 현장)으로 보낸다. 따라서 두 시스템은 같은 엠클릭 데이터를 공유하되 쓰는 목적이 다르다.

| 구분 | MERITTOUR dashboard | SaiZen 자동화 앱 |
|---|---|---|
| 위치 | 한국 본사 | 일본 현장 |
| 언어 | 한국어 (고객) | 일본어 (현장) |
| 목적 | 예약 점검·고객 안내·발송 | 현장 운영 산출물 생성 |
| 입력 | 엠클릭 3종 + APIS | 엠클릭 2종(예약리스트·일행별예약) |
| 산출 | 화면 조회·알리고 양식·요금 검증 | 네임택·배정표·청구서 |

공유 표준(양쪽 프로젝트에 모두 반영): eventSeq 결합 키, 숙소 분류 규칙, 그룹코드 체계, 라운딩 용어, 라이트 모드(다크 없음).

> 단, **브랜드 컬러는 프로젝트별로 다르다.** SaiZen 화면 UI는 사이젠 팔레트(올리브그린 #647548 / 밝은 세이지 #9CB07A + 쿨 뉴트럴 배경 #F4F6F2, 차콜 텍스트 #3A463A)를 쓰며, 같은 프로젝트의 **SaiZen Hub와 톤을 맞춘다**(흙갈색·웜미색 금지). 메리트투어는 자체 색을 유지한다. 사이젠 인쇄물(청구서·네임택 등)의 네이비는 별도 검증 전까지 미수정 보존한다.
