**결정되면 작성할 것**(급한 순)

1. **전기카트 전량 취소가 저장되지 않는다**(대수 검사 「0보다 커야 한다」) — 1대 신청 팀의 취소가 거부되고 다시 열면 대수·청구가 되살아난다. 검사를 「0 이상」으로 + 화면 3줄 + 손님 코스 화면의 전기카트 대수 식.
2. 마감·무효 처리한 계산서 줄이 원본(카트·별주·싱글차지)이 바뀌면 지워지고 다시 만들어지는 것 — 권장: 마감된 줄은 두고 차액만 새 줄, 마감한 팀의 카트 저장은 막는다.
3. 방 정원 가드·검수식의 「기간이 겹치는 행의 합」 → 「밤 단위 최대」(정상 배정을 거부할 수 있다) + 검수 범위 최근 7일 이후.

6. 통계(경영·예약 추이·방문)를 「보기」로만 준 계정에 숫자가 나오지 않는 것 · 現地精算表 보기 권한의 차감·가산·비고.

### 방배정
- 층 [비우기]의 범위 — 달 전체(지금) / 보고 있는 하루만 / 버튼 삭제.
- 날짜 칩 「미N」에 대기 예약을 셀지 · 이번 달을 열 때 기준일(1일 / 오늘).
- 일본어·영어 화면의 판매구분 표시명(방 타입·숙소·층은 6차에 반영).
- 유동층(12·8·5층) 「한 층에는 한 가지 박수만」 — 같은 실행 안에서는 적용되지 않고 보는 달에 따라 결과가 달라진다(규칙을 없애고 12 → 8 → 5층 순서만).
- 비고의 다른 줄에 「취소·대기·보류·불가」가 있으면 전원 싱글 요청이 보류 없이 둘씩 배정되는 것(막는 낱말은 싱글이 적힌 줄에서만 찾고, 걸리면 보류).
- 2026 관내별장 넘침에서 소보 5호에 서로 다른 2인 팀 둘이 함께 들어갈 수 있는 것(섞지 않는다).
- 일반 짝의 컴팩트 순서 — 지금은 층이 먼저. 「컴팩트는 전 층의 스탠다드 트윈을 다 쓴 뒤」가 맞다면 코드를 고친다.
- 홀수 팀의 「싱글 없음」을 싱글 1방으로 세는 것(트리플이면 비고에 적는다는 전제).

### 정산
- 숙소 칩으로 한 숙소만 볼 때의 차감 합계·정산액(Net) — 차감은 숙소로 나뉘지 않는다(숙소를 고른 동안에는 차감·Net 을 숨긴다).
- 주보·월보 「미정산 체크아웃」에 체크아웃일이 아직 오지 않은 팀(빼고 「예정 N팀 제외」).
- 시즈 단가 표기 — 정산표 16,000 ↔ 시즈 예약표 설명의 별채 가산 · 시즈 별채 온천 사전신청비를 계산서에 올릴지.
- 석식 별주 매출을 어느 날 일보에 잡을지.
- 세율 섞인 팀의 領収書를 프론트 데스크에서도 세율별로 낼지(지금은 정산 화면에서만).

- 편명·시각이 바뀌면 입력해 둔 배차가 어느 카드에도 붙지 못한다 — 「붙지 못한 배차 N건」 표시를 둘지(배차 입력 0건).

- 묶음 안에 대기 예약 팀이 있으면 그 팀이 번호 자리를 차지한다(남은 팀이 1·3 으로 건너뛰고, 대기가 확정으로 바뀌면 번호가 달라질 수 있다 — 인쇄물 네 화면의 기존 규칙이고 33차에 화면 쪽 공용 헬퍼도 같게 맞췄다. 운영 0건. 지금 규칙 유지 / 대기 팀을 번호에서 뺀다).
- 안내문의 B5 — ISO 176×250mm(지금) / 일본 규격 182×257mm.
- 가타카나 표기 선택(튜·듀 = テュ, i 뒤의 NGW).

## 4. 저장소 · 문서 운영

- **git 기록에 남은 실명** — 지금 파일에서는 지웠지만 과거 커밋에는 남아 있다. 기록을 다시 쓰고 강제로 올리면 지워지지만 되돌릴 수 없다(GitHub 캐시는 별도 요청). 비공개 전환은 유료 플랜 필요.
- **CLAUDE.md 크기** — 규칙은 앞쪽 일부이고 나머지는 날짜별 기록이라 매 세션 통째로 읽힌다(기록을 `docs/` 로 옮기고 규칙만 남긴다).
- **문서의 대표 실명·지분 문장** — `CLAUDE.md` · `docs/01_프로젝트_지침.md`(「Min(대표)」로 통일하고 지분 문장은 지운다 / 그대로).
- **커밋 꼬리말** — 스킬 문서는 「모델 식별자를 커밋에 넣지 않는다」인데 실제 커밋에는 세션 도구가 붙이는 줄이 있다(문장을 지운다 / CLAUDE.md 에 「넣지 않는다」를 명시).
- **CI** — main 에 바로 올리는 방식이라 CI 가 실패해도 이미 배포된 뒤다(지금처럼 두고 배포 전 `npm run verify` 유지 / Pages 를 Actions 배포로 바꿔 통과 뒤에만 배포).
- **매뉴얼 파일** — 방배정 직원·손님 설명 매뉴얼의 PDF·DOCX 는 15차·29차 문구 정정을 반영해 다시 만들었다(저장소에는 md 만).
- **옛 기록 문서** — `docs/01·02·03`·`SESSION_HANDOFF.md`·`blueprint.html`·`work-blueprint.html` 은 머리 배너와 `docs/00_README.md` 의 「옛 기록」 묶음으로만 구분해 두었다(`docs/archive/` 로 옮긴다 — 사이트 주소가 바뀌므로 링크 확인 뒤).
- **추적 파일 검사의 범위** — 막는 것은 표·문서·압축·DB·키 파일 확장자 32종(이름의 모든 토막에서), `.env` 류, `id_rsa` 류·`.netrc`·`.pgpass` 와 비밀값 꼴 8종이다. pptx 는 `docs/deployment-hardware.pptx` 1개가 올라가 있어 넣지 않았다(그 파일을 계속 둘지부터). 사진(여권·명단을 찍은 것)과 데이터가 든 `.sql`·`.json` 은 이름으로 가릴 수 없다.
- **CLAUDE.md 규칙 절에 남은 옛 표기** — §6 `originMap`·「v14.0」, §7·§11 의 「⑤」(없어진 도구의 탭 번호), §8 「앱 색을 바꾸기 전」, §13 본문(절 머리에 「2026-06 당시의 설명」 표시만 달았다). 규칙 문장이라 손대지 않았다(표기만 정리한다 / 그대로).
- **검사 스크립트의 길이** — 문법 검사·대기 예약 검사가 각각 수백 줄로 늘었다(글자를 코드·문자열·주석으로 가리는 공용 도구 `scripts/lib/js-skeleton.mjs` 위에서 헬퍼 정의 범위·조회 체인을 본다). 동작은 `tests/check-scripts.test.mjs` 로 고정했다(그대로 / 단순 기준으로 되돌린다 — 되돌리면 정산 화면·홈에서 났던 꼴과 대기 누락 7곳을 다시 놓친다).
- **검사가 올바른 코드를 막는 경우** — 헬퍼 이름(esc·tx·lang·toast)과 같은 매개변수를 함수처럼 부르는 코드, 선언 없이 담은 전역, 뼈대가 읽지 못하는 드문 문법(닫는 중괄호 바로 뒤의 나눗셈 `{} / 2` 등)은 오류로 알린다(안내대로 최상위 선언·괄호로 풀어 적는다). 대기 검사도 호출 밖에서 다른 값에 섞은 select 변수, 괄호로 묶은 조회에 붙인 필터, 중첩 임베드, 수식어를 변수로 이어 붙인 임베드, 변수에 담아 두었다가 뒤에서 조건을 붙이는 조회는 필터로 통과시키지 않고 사유 주석을 요구한다. 지금 화면 0곳. 연결·열 확인의 허용도 좁다 — 받은 값에서 `r.status` 를 함께 읽거나 `r && r.error` 로 쓰면 사유 주석을 요구한다(`const { error, status } = await …` 로 받으면 통과). 영어 화면 문구에 낱말 bookings 를 이어 붙인 글자( `n + ' bookings'` )도 사유 주석을 요구한다. 전역 객체의 다른 이름(`const w = window`)은 같은 스크립트에 같은 이름의 매개변수·대입이 있으면 인정하지 않는다(`window.이름 =` 으로 적는다).
- **검사가 보지 못하는 것** — 각 스크립트 머리말의 「보지 못하는 것」에 적어 두었다: 표 이름 글자 없이 FK 열·제약 이름만으로 적은 임베드, 연쇄 대입으로 옮긴 select 변수, 안쪽 헬퍼 호출에 붙은 사유 주석(대기 검사) · select 변수의 「가림」 판정이 넓은 네 꼴(대기 검사) · 콜론 없는 줄임 속성이 주석에 먹힌 것, 다른 속성 값 안에 「 src=」·「 type=」 글자가 든 여는 태그와 태그 밖 글자로 적힌 데이터 블록 `<script type=…>`(문법 검사·뼈대의 HTML 읽기) · 쪼개거나 한 번 더 인코딩한 비밀값과 이미 지난 커밋(추적 파일 검사). 새 코드는 표 이름이 글자로 보이는 꼴로 적는다.
- **후속 후보 — 같은 이름의 최상위 선언** — 한 화면의 스크립트 둘이 같은 이름을 `let`·`const` 로 다시 선언하면 뒤 스크립트가 통째로 실행되지 않는다(문법 검사는 스크립트를 하나씩 보므로 통과한다). 지금 화면 0곳이라 검사에 넣지 않았다(넣는다 / 그대로).
- **검사 스크립트의 남은 반박 검토** — 배포 전 최종 검토는 대기 예약 검사·문법 검사 두 관점만 돌렸다(사용 한도). 추적 파일 검사·문서 대조 관점은 돌리지 않았다 — 추적 파일 검사의 3차 변경분은 직접 읽어 확인했고 그 규칙의 변이 37건은 테스트가 잡는다(돌린다 / 그대로).

## 5. 검수에서 굳어진 규칙(요약)

1. 조회 실패는 「없음」이 아니다 — 실패한 결과로 삭제·자동 저장·자동 배정을 하지 않고, 앞 상태를 화면에 남기지 않는다.
2. 날짜·월·기간을 바꾸는 조회는 순번으로 낡은 응답을 버리고, 전역은 끝에서 한 번에 바꾼다.
3. 저장은 시작할 때의 대상(날짜·줄)을 잡고 끝까지 그것만 쓴다. 바꾸려는 열만 보낸다. 반영된 행 수를 본다.
4. 「그 달의 팀」 조회는 그 화면이 세는 모든 것(말일 밤·1일 아침)을 덮는다 — 경계 한 칸을 다른 모양의 조회로 대조한다.
5. 화면·인쇄·엑셀은 같은 판정 함수로 같은 줄을 낸다. 인쇄물의 언어는 양식이 정한다.
6. 판정 로직을 고치면 배포 전에 반박 검토에 넣고, 운영 데이터의 실제 문장으로 전·후를 대조한다.
7. DB·주소·파일에서 온 값은 그 줄에서 이스케이프한다. 링크로 쓰는 값은 꼴을 검사한다.
8. 같은 표에 두 화면이 같은 표시로 쓰면, 정리·삭제는 자기가 실제로 계획하는 범위로 한정한다.
9. 설명서·문서의 예시는 실행해 본 뒤 적고, 지어낸 이름만 쓴다.
10. 옛 번호 SQL 파일은 다시 실행하지 않는다 — 적용 상태는 `00_VERIFY.sql`, 변경은 새 번호 파일.
11. 검사 스크립트와 그 테스트도 검수 대상이다 — 읽지 못한 것은 통과가 아니라 오류로, 테스트는 판정·건수까지 고정하고 규칙을 하나씩 망가뜨려 실패하는지 본다.
