# 구마모토 시내 · 트라이얼 수배 목록(手配リスト) — 설계 메모 (2026-11-02)

현지(자회사) 담당 회사가 쓰던 **월별 수배서 목록(xlsx)** 과 **요금표(xlsx)** 를 받아 우리 시스템 안으로 옮긴 기록이다.
두 파일 자체(금액·고객 이름·여행사 상세 포함)는 저장소에 두지 않는다(CLAUDE.md §3-2). 여기에는 **열 대응과 규칙만** 남긴다.

Min 지시(2026-11-02): 「이 파일 그대로가 아닌 우리 스타일에 맞게 — 안 봐도 되는 정보는 빼고, 꼭 봐야 하는 내용이면 여기에 맞춰서, 기본값은 넣을 수 있게」
· 차량 하이에스 3 · 마이크로버스 1(증설 가능) · 담당 3명 · 호텔 블록 워싱턴 트윈 4 · 아마넥 트윈 4(밤마다) · 싱글 블록 없음(싱글 이용은 요금 책정)
· 골프장은 파일에서 정리한 목록으로 등록 · 타 여행사 팀도 엠클릭에 넣어 메리트투어가 함께 관리(담당자 지정) · 여행사 명은 엠클릭에 따로 적음.

## 2. 요금표(新料金 2026.12 · 日別 料金表) → 규칙

- 1인 요금 = **밤마다 호텔**(객실 종류 × 밤 구분) + **라운드마다 골프**(날 구분) + **引率**(밤마다 1일분 + 귀국일분) + 호텔 가산(아마넥·타우 류) + 1인 가산.
- **밤 구분**: 금·토·일·祝日·祝前日 밤 = 휴일 요금 / 그 외 평일 — 현지 日別 料金表 365일(2026-11~2027-10)과 대조해 전부 일치(`SZCore.partnerNightType`).
- **골프 구분**: 토 / 일·祝日 / 그 외(금요일 포함 평일) (`SZCore.partnerGolfType`).
- 파일의 4泊5日(월~금) 싱글·3泊4日(금~월) 싱글·트윈 합계는 이 식과 1円까지 일치했다. 4泊5日 트윈 합계만 파일 쪽 더하기가 2,000 어긋나 있었다(식의 결과를 믿는다).
- **숫자는 저장소에 없다** — 기본 설정 › 요금표(partner_settings.rates)에 담당자가 넣는다. 테스트는 가상 요금으로 식만 고정.
- 싱글: 블록이 없으므로 싱글 객실이 있으면 요금(팀 입력 또는 요금표 싱글 단가)이 꼭 있어야 한다 → 없으면 「싱글 요금 미정」 빨강 + 검수 짝 `partner_single_norate`.

## 3. 표 · 권한 · 검수

- SQL 160: `partner_ops`(팀별 1행) · `partner_golf` · `partner_dispatch` · 등록표 `partner_hotels`(블록·가산)/`partner_courses`/`partner_vehicles`(정원)/`partner_staff` · `partner_settings`(rates·partner_defaults) · `partner_bookings.agency`.
