# 구마모토 시내 · 트라이얼 수배 목록(手配リスト) — 설계 메모 (2026-11-02)

현지(자회사) 담당 회사가 쓰던 **월별 수배서 목록(xlsx)** 과 **요금표(xlsx)** 를 받아 우리 시스템 안으로 옮긴 기록이다.
두 파일 자체(금액·고객 이름·여행사 상세 포함)는 저장소에 두지 않는다(CLAUDE.md §3-2). 여기에는 **열 대응과 규칙만** 남긴다.

Min 지시(2026-11-02): 「이 파일 그대로가 아닌 우리 스타일에 맞게 — 안 봐도 되는 정보는 빼고, 꼭 봐야 하는 내용이면 여기에 맞춰서, 기본값은 넣을 수 있게」
· 차량 하이에스 3 · 마이크로버스 1(증설 가능) · 담당 3명 · 호텔 블록 워싱턴 트윈 4 · 아마넥 트윈 4(밤마다) · 싱글 블록 없음(싱글 이용은 요금 책정)
· 골프장은 파일에서 정리한 목록으로 등록 · 타 여행사 팀도 엠클릭에 넣어 메리트투어가 함께 관리(담당자 지정) · 여행사 명은 엠클릭에 따로 적음.

## 2. 요금표(新料金 2026.12 · 日別 料金表) → 규칙

- 1인 요금 = **밤마다 호텔**(객실 종류 × 밤 구분) + **라운드마다 골프**(날 구분) + **인솔 요금**(그 팀 **상품**의 줄: 묵는 밤마다 1박당 — 귀국일 요금 없음 · 송영 비용 포함) + 호텔 가산(아마넥·타우 류) + 1인 가산.
- **밤 구분**: 금·토·일·祝日·祝前日 밤 = 휴일 요금 / 그 외 평일 — 현지 日別 料金表 365일(2026-11~2027-10)과 대조해 전부 일치(`SZCore.partnerNightType`).
- **골프 구분**: 토 / 일·祝日 / 그 외(금요일 포함 평일) (`SZCore.partnerGolfType`).
- 파일의 4泊5日(월~금) 싱글·3泊4日(금~월) 싱글·트윈 합계는 이 식과 1円까지 일치했다. 4泊5日 트윈 합계만 파일 쪽 더하기가 2,000 어긋나 있었다(식의 결과를 믿는다).
- **숫자는 저장소에 없다** — 기본 설정 › 요금표에 담당자가 넣는다. 테스트는 가상 요금으로 식만 고정.
- **기간별·대상별 요금표(2026-11-03, Min 「호텔·골프장·송영 각각 · 기간마다 · 2~3월 평일/주말, 그 안에 또 다를 수 있고」)**: SQL 161 `partner_rates` 1행 = 종류(hotel/golf/transfer/guide) × 대상(호텔·코스·차량 id, null=공통) × 기간(from/to, null=상시) → `prices` jsonb. 화면은 「기간」 묶음(이름·시작~종료)마다 호텔별·코스별·차량별 칸을 한 번에 편집([이 기간 저장]·[이 기간 복사]). 해석(`SZCore.partnerPrice`) = 대상 지정 > 공통 · 좁은 기간 > 넓은 기간 · 칸 단위 폴백 → 「2~3월」 위에 「2/10~2/14」를 토요일 골프 칸만 적어 두면 그 칸만 바뀐다. 옛 `partner_settings.rates`(공통 한 벌)는 행이 없을 때 폴백.
- **송영 요금은 없다(Min 2026-11-11 「송영에는 비용 넣는 거 없애 · 인솔요금으로 두 개를 통합」)**: 송영 비용은 인솔 요금에 들어 있고 견적에 따로 더하지 않는다. 차량은 이름·정원·사용만 등록한다(정원 = 자동 배차에서 차량을 나누는 기준). `partner_rates.kind='transfer'` 값은 표에 남아 있어도 화면·견적이 읽지 않는다(등록된 줄 0).
- **인솔 요금 = 상품별(Min 2026-11-11 「시내투어와 트라이얼이 다르다 · 1박당 비용 · 상품도 정하게」)**: `partner_rates` kind=`guide` 줄의 `ref_id` = **상품 번호**(`SZCore.partnerBrandRef`: 구마모토 시내 1 · 트라이얼 2 · null = 전 상품 공통 — 새 컬럼 없이 호텔·코스와 같은 「대상 지정 > 공통」 규칙을 그대로 쓴다. 번호는 DB 에 저장되므로 바꾸지 않는다). 1인 기준, 칸 = `day`(1박당) 하나 — **귀국일 요금(`last`)은 2026-11-11 Min 「귀국일 요금은 없애줘」로 폐지**(계산·기본 설정 칸·DB 값 모두 제거, 옛 값이 남아 있어도 읽지 않는다). 그 상품 줄 > 공통 줄 · 좁은 기간 > 넓은 기간 · 칸 단위 폴백. 기본 설정의 인솔 표는 줄마다 「상품」 select, [＋ 요금 줄]로 다른 상품·기간을 더하고, 같은 상품·같은 기간 줄이 둘이면 저장을 거부한다.
- **호텔 블록 사용/사용 안 함**(`partner_ops.use_block`, 기본 true): 끄면 그 팀 객실은 블록 띠·블록 초과·검수 ㉓에서 빠진다(별도 예약·블록 외).
- 싱글: 블록이 없으므로 싱글 객실이 있으면 요금(팀 입력 또는 요금표 싱글 단가)이 꼭 있어야 한다 → 없으면 「싱글 요금 미정」 빨강 + 검수 짝 `partner_single_norate`.

## 2-1. 엠클릭 비고로 자동 채움 · 송영 규칙 · 저장 버튼 (Min 2026-11-03)

- **비고 양식(권장)**: `여행사: ○○ / 워싱턴 / 싱글룸 2 / 골프장: 그랜드챔피언, 추오, 그린힐` — 날짜는 `11/5 추오`·`2일차 추오`·`둘째날 추오`처럼 코스 이름 앞에. 순서·구분자는 자유(한 줄에 섞여 있어도 읽는다).
- **읽는 규칙**(`SZCore.partnerRemarkPlan`, step1 적재와 화면 「비고대로 채우기」가 같은 함수): 호텔=등록표 이름·별칭이 처음 나오는 것 / 객실=「싱글룸 N」(단위 없는 수도)·전원 싱글·이름 나열·홀수 1명 + 「트리플 N」 → 나머지 2명씩 트윈, 남는 1명은 싱글 / 골프장=적힌 순서대로 날짜별 1라운드(날짜 없으면 이어서 하루씩 — 코스 수가 박수보다 적으면 도착 다음 날부터, 같거나 많으면 도착일부터, 추정 날짜는 화면에 「날짜는 추정(확인)」) / 여행사=`partnerAgency`(비고 「여행사: ○○」 → 상품명 「여행사 ○○투어 [2박 3일] …」 순, Min 2026-11-04 — 비고가 그 예약 고유라 먼저; 상품명 여행사가 있을 때만 서명(auto_sig)에 들어가 기존 서명은 불변).
- **별칭**(SQL 162 `partner_hotels/courses.aliases`, 기본 설정 「별칭」 열): 「추오/츄오/중앙」「그린힐」「미나미아소」처럼 Min 이 쓰는 표기를 쉼표로. 긴 별칭이 우선(「미나미아소트라이얼」 안의 「아소트라이얼」은 안 잡힌다). 영문 별칭은 단어 경계(restaurant 안의 tau 오탐 방지).
- **언제 채우나**: step1 적재 직후 **수배 행이 없는 새 팀만** 자동(호텔·객실 수·담당 기본값·골프 줄 `auto`·`auto_sig`). **수배 목록 화면을 열 때도 자동(2026-11-11, §2-4)** — 수배 행이 없는 팀은 새 행, 비고가 바뀐 팀은 빈 칸만. 이미 넣은 값이 바뀐 비고와 다를 때만 목록에 「비고 변경됨」 — 담당자가 [비고대로 채우기]를 눌러 초안으로 받은 뒤 [저장]. (옛 툴바 [비고대로 일괄 채우기(N)] 버튼은 없앴다.)
- **송영 차량**(`SZCore.partnerVehiclePlan`): 20명 미만 = 하이에스(정원 9)를 등록 순서로 채움(8명=1대·12명=2대·19명=3대), 20명 이상 = 마이크로버스(정원 큰 차) 먼저, 모자라면 하이에스. 배차 제안은 구간마다 차량 수만큼 줄(비고 「1/2대 · 9명」).
- **송영 구간**(`SZCore.partnerLegPlan`, 공항·호텔·골프장 서로 50분 `PARTNER_TRAVEL_MIN`): 도착일=공항→호텔 / 그날 골프면 공항→골프장(도착+115분 안에 티오프면 호텔 경유) · 중간일=호텔→골프장(티 −60)·골프장→호텔 · 귀국일=호텔→공항(출발편 −120) / 그날 골프면 골프장→공항. 저장 행은 출발·경유·도착 지점(SQL 162 `from_pt/via_pt/to_pt`, 없으면 `leg` 로 해석)으로 표기·인쇄(配車表 「空港→ホテル→ゴルフ場」).
- **저장 버튼**(Min 「그냥 수정이 되게 되어 있어서 위험함」): 팀 상세의 모든 입력(호텔·객실·골프 줄·배차 줄·체크·메모·[비고대로]·제안 추가)은 **초안**에만 쌓이고 [저장]을 눌러야 DB 에 쓴다([취소]=버림, 다른 팀으로 이동·월 이동·창 닫기 전에 확인). 날짜별 배차 표와 기본 설정 등록표도 줄을 고친 뒤 [저장(N)]. 요금표는 이미 [이 기간 저장].
- **비고 줄 기본 펼침**(Min 2026-11-04 「비고란은 디폴트를 펼쳐짐 상태로」): 목록에서 비고가 있는 팀은 대표자 칸 아래 줄에 엠클릭 현지비고·비고 원문이 **항상 펼쳐져** 있고, 대표자 칸의 [비고 닫기]로 그 팀만 접는다(`RMK_CLOSED`, 접은 상태는 재렌더에도 유지 · 팀 선택과 무관). 2026-11-03 의 「클릭해서 펼치기」(기본 접힘)를 뒤집은 것.
- **담당자**: 타츠마루·카이야(2026-11-03 등록, 세 번째는 추후).

| 같은 글 두 번 | 비고와 현지 비고를 이어 읽어 **골프장을 적으면 라운드가 두 배**가 될 상태였다 | `partnerRemarkPlan([비고, 현지비고])` — 같거나 한쪽이 다른 쪽을 품으면 한 번만 읽는다. 서명(auto_sig)은 종전 식 그대로 |
| 자동 채움 | **수배 행이 하나도 안 만들어졌다** — 등록하는 계정(데이터 등록 권한만)에는 `partner_ops` 쓰기 권한이 없어 RLS 에 막힘. 등록 로그에는 매번 「자동 채움 실패」 경고 | **SQL 165(2026-11-11 적용)** — 등록 계정에 권한이 없어도 등록 때 새 팀의 수배 행이 만들어진다(아래 §2-3). 함수가 없는 DB 에서는 종전 경로 + 안내 한 줄 |

- 여행사 상품을 자사 손님이 쓰는 경우(상품명에 「여행사」만 있고 끝 이름 없음)는 「여행사 미기재」로 남는다 → 비고에 「여행사: 메리트투어」.

- 검증: 단위테스트(실제 양식 표본)·jsdom(수배 목록 일괄 채우기·등록 화면 권한 경로) — `npm run verify`.

## 2-3. 등록 시점 자동 채움 = 서버 함수 2개 (SQL 165, Min 2026-11-11 「등록할 때 자동으로 만들어지게 SQL 변경해줘」)

- **왜 정책을 넓히지 않았나**: 호텔 등록표에는 가산 금액·블록이, `partner_settings` 에는 옛 요금이 있다. 데이터 등록 권한에 표 읽기·쓰기를 열면 그것까지 보인다 → 표의 RLS 는 그대로 두고 좁은 함수만 연다.
- `partner_autofill_refs()` — 비고 해석에 필요한 것만 돌려준다: 호텔·골프장의 id·이름·별칭·사용 여부 + 상품별 기본 호텔/담당. 금액·블록·요금표 없음.
- `partner_autofill(p_rows)` — **수배 행이 없는 팀에만** `partner_ops` 1행(+비고의 골프장 줄 `partner_golf`, auto)을 넣는다. 이미 있는 팀은 건드리지 않는다(`on conflict do nothing`, 그 팀에 골프 줄이 있으면 골프도 안 넣음). 값 검사: 없는 호텔·코스 id 는 비우거나 건너뜀 · 객실 수 0~99 · 골프 날짜는 그 예약 기간 안 · 한 번에 500팀. 결과 `{teams, skipped, golf, hotels, bad}`.
- 둘 다 `security definer` · 로그인 전용(anon 불가) · 마스터 또는 데이터 등록(step1) 또는 구마모토·트라이얼 권한자. anon 실행 가능 security definer 는 15 그대로.
- 해석(비고 → 호텔·객실·골프장)은 종전처럼 `SZCore.partnerRemarkPlan` 하나 — step1 이 계산해 함수에 넘긴다(`partnerPlanRows`). 등록 때마다 그 파일의 예약 전부를 보내고 함수가 이미 있는 팀을 건너뛴다(로그 「수배 자동 채움: 새 팀 N」).
- 함수가 없는 DB(165 미적용)에서는 종전 직접 경로(권한 있는 계정만 성공, 그 밖은 안내 한 줄). 165 전에 들어온 팀·비고를 나중에 고친 팀은 수배 목록 화면이 열릴 때 맞춘다(§2-4).
- 검증: 운영 DB 롤백 시험(등록 권한만 있는 계정·담당 계정·권한 없는 계정·미로그인 × 삽입/재호출/잘못된 값) + 실제 등록분 21건 입력(새 팀 20·건너뜀 1·객실 인원=예약 인원 20/20) + jsdom(등록 화면이 표에 직접 쓰지 않고 함수 2개만 호출·재등록 시 0건).

### 2-4. 화면을 열 때 자동 반영 (Min 2026-11-11 「비고에 다 있는데 왜 적용이 안 됨 · 클릭은 번거롭다」)

수배 목록(`partner_ops.html`)은 읽은 직후 `autoSync()` 를 한 번 돈다. 버튼·확인창 없음.

| 대상 | 하는 일 | 안 하는 일 |
|---|---|---|
| 수배 행이 없는 팀(비고에서 읽은 것이 있음) | 호텔(없으면 상품별 기본)·객실 수·담당 기본값·골프 줄(`auto`)·서명으로 새 행 — 한 번의 요청, `ignoreDuplicates` | 그 사이 다른 사람이 만든 행은 덮지 않는다 |
| 수배 행이 있고 비고 서명이 다른 팀 | **빈 칸만**: 호텔 없음 → 비고 호텔 / 객실 수 전부 0 → 비고 객실 수 / 골프 줄이 없는 날 → 그날 코스 | 값이 있는 칸(호텔·객실 수·그날 골프 줄·티타임)은 그대로 |
| 그 뒤 저장값 = 비고에서 읽은 값 | 서명만 맞춘다 → 「비고 변경됨」 사라짐(비고에 항공 메모만 덧붙인 경우의 소음 제거) | — |
| 그 뒤 저장값 ≠ 비고 | 서명을 그대로 둔다 → 「비고 변경됨」 유지 | 사람이 [비고대로 채우기] → [저장]으로 정한다 |

- 읽기 전용 계정: 띠가 떠 있으면 시도하지 않고, RLS 거부·0행 수정이 돌아오면 그 세션에서는 다시 시도하지 않는다(오류 표시 없음, 「비고 미반영」 배지는 그대로).
- 기록: 새 행 `remark_auto`, 빈 칸 보완 `remark_auto_fill`(무엇을 채웠는지) — `change_log` 한 번에. 서명만 맞춘 것은 기록하지 않는다.
- 다시 열면 쓰기 0건(멱등). 달을 바꾸는 중에 끝난 응답은 버린다(`LOAD_TOK`).
- 상태 칸 H·G·日·請 는 「명단을 호텔에 보냈다」 같은 사람의 작업 기록이라 자동으로 켜지 않는다.
- 검증: jsdom 28건(새 팀·빈 칸 보완·충돌 유지·서명만·읽기 전용 3경로·멱등·i18n) + 기존 스모크 회귀.

### 2-5. 화면 개편 — 한눈에 띠 · 필수 확인 · 실효 배차 · 견적 수정 · 블록+요금 한 줄 (Min 2026-11-11)

Min 요청: 「배차 날짜별 메뉴는 없애고 수배 목록에서 같이 한눈에」「골프장 블록·송영 블록·담당자 배정도 호텔 블록 아래에」「상태 설정 4개는 없애」「비고대로 채우면 되지 왜 채우기 기능이 또 있나」「필수 확인 목록은 더 강조」「견적 자동은 좋다, 수정 기능도」「기본 설정에서 골프장도 호텔 블록처럼(시작·종료), 블록 가격도 하나로 합쳐 같이 저장」.

**§2-4 의 「빈 칸만 채우고 다르면 배지 + [비고대로 채우기]」 규칙은 폐기**하고 아래로 바꿨다.

| 무엇 | 지금 규칙 |
|---|---|
| 비고 서명(`partner_ops.auto_sig`) | 해시가 아니라 **읽은 값 자체**: `v2\|h<호텔 id>\|t<트윈>\|s<싱글>\|r<트리플>\|g<날짜@코스,…>` |
| 비고가 바뀌었을 때 | 화면을 열 때 옛 서명과 새로 읽은 값을 **칸별로 비교** — 비고에서 바뀐 칸(호텔 / 객실 수 / 그 날짜 코스)만 따라간다. 빈 칸은 언제나 채운다. 사람이 고친 칸은 비고의 그 부분이 바뀌기 전까지 그대로 |
| 비고에서 빠진 라운드 | 손대지 않은 자동 줄(`auto`, 티타임·비고·名簿 없음)일 때만 삭제 |
| 옛 서명(해시)·서명 없음 | v2 로 바꿔 적는다. 옛 해시가 지금 비고와 다르면 호텔·골프는 비고를 따르고 객실 수는 비어 있을 때만 |
| 수배 행이 없는 팀 | 비고가 비어 있어도 행을 만든다(호텔=상품별 기본, 담당=기본값) |
| 배차 | **실효 배차** = 저장한 줄 + 항공편·티타임에서 계산한 자동 줄(같은 날짜·구간에 저장 줄이 있으면 자동 줄은 빠짐). 자동 줄은 저장하지 않아도 목록·띠·견적·配車表에 반영되고, 상세에서 고치면 그 (날짜·구간)의 자동 줄이 초안으로 들어가 [저장] 대상이 된다 |
| 편(run) | 같은 차량 + 같은 시각 + 같은 구간 = 1편(합승). 적재 > 정원 = 초과, 같은 차량·같은 시각에 구간이 다르면 겹침 — 둘 다 빨강 |
| 자동 줄의 차량 | 팀마다 따로 잡지 않고 **그달 전 팀을 한 번에** 나눈다(`buildEff`): 저장 줄이 먼저 자리를 차지 → 자동 줄은 팀 순서대로, 지금 차량에 자리가 있으면(같은 시각·같은 구간 합승, 정원 이내) 그대로, 없으면 등록 순서의 다음 차량(20명 미만 팀은 작은 차 먼저). 골프장이 낀 구간은 **어느 골프장인지까지**가 편의 키(다른 골프장은 합승 아님). 시각 없는 줄은 건드리지 않는다. 실데이터 12월: 같은 편 8명 두 팀이 둘 다 1호차를 잡아 「정원 초과」로 뜨던 2팀이 사라짐 |
| 월간 가동 현황(月間 稼働状況 — 2026-11-11 개명, 옛 「이달 한눈에」) | 호텔 블록(트윈 사용/확보) · 골프장(조 수 = Σ 올림(인원÷4), 블록이 있으면 사용/확보) · 송영(차량별 편수, 칸 클릭 = 그날 配車表) · 담당자(도착일~귀국일 맡은 팀 수, 미지정 줄) |
| 필수 확인(빨강) | 호텔 미지정 · 객실 수 미입력 · 객실 수≠인원 · 싱글 요금 미정 · 차량 정원 초과·겹침 |
| 확인(주황) | **블록 초과**(Min 2026-11-11 「주황으로」 — 정상 상황이라 빨간 띠를 만들지 않는다) · 골프 미지정 N일 · 담당 미지정 · 여행사 미기재 · 항공편 없음 · 요금 없음 |
| 없앤 것 | 「배차(날짜별)」 탭 · 상태 체크 4종(H·G·日·請 — DB 컬럼은 휴면) · [비고대로 채우기]·[인원으로 제안]·[비고대로 일괄 채우기] · 라운드별 名簿 체크 · 기간 묶음 요금표 패널 |
| 견적 수정 | `partner_ops.quote_fix` jsonb `{twin,single,triple,total}`(SQL 166). 1인 요금을 적으면 팀 합계 = 트윈×트윈 실×2 + 싱글×싱글 실 + 트리플×트리플 실×3, `total` 을 적으면 그 값. 비우면 자동. 수정한 팀은 「요금 없음」 판정을 하지 않는다 |

**블록 초과는 막지 않는다(Min 2026-11-11 「블록 설정 이상의 객실도 있을 수 있어, 그거는 지금처럼 초과표시로 충분함」)**: 블록(호텔 트윈 실·골프장 조)은 확보해 둔 수량일 뿐 상한이 아니다 — 블록을 넘는 객실은 따로 예약해서 쓰는 정상 상황. 화면은 저장을 막거나 경고창을 띄우지 않고 띠의 빨간 칸·주황 「블록 초과」 배지(「확인」 묶음 — 줄 왼쪽 빨간 띠 없음, 팀 상세의 밤별 사용/확보 배지도 주황)로 **표시만** 한다. 저장 차단·자동 조정을 넣지 않는다.

**기본 설정 = 한 줄에 블록과 요금**(표마다 [저장] 한 번):

- 줄 종류: `공통`(대상 지정 없음, `partner_rates.ref_id` null — 비운 칸은 이 값) / 호텔·골프장·차량 한 곳(이름·블록·기간·요금) / 그 대상의 `다른 기간 요금`.
- 블록은 등록표에 그대로(`partner_hotels.block_twin/from/to`, `partner_courses.block_groups/from/to` = SQL 166), 요금은 `partner_rates`(kind·ref_id·기간·prices). **대상 줄의 기간 = 블록 기간 = 그 줄 요금의 기간**(기간을 고치면 둘이 같이 움직인다). 기간이 다른 요금은 [＋ 기간] 줄.
- 저장 = 등록표 변경분 update + 요금 delete → upsert(id 있는 줄) → insert(새 줄, id 없이 따로 — 묶음 upsert 에 섞으면 id 가 null 로 간다). 요금 칸을 전부 비운 줄은 그 요금 행을 지운다.
- 요금 해석 순서는 종전 그대로(`SZCore.partnerPrice`): 대상 지정 > 공통, 좁은 기간 > 넓은 기간, 칸 단위 폴백.
- SQL 161 전 = 요금 칸 잠김(등록표는 저장) / SQL 166 전 = 골프장 블록·기간 칸 잠김(요금은 기간 없이 저장)·견적 수정 칸 잠김.

검증: jsdom `t-partner-v3`(44)·`t-partner-defs`(36)·`t-partner-auto`(28)·`t-partner-minfmt`(27)·`t-partner-rmk`(8)·`t-partner-hotellist`(11)·`t-partner`(26) + Playwright 1536/1280(가로 넘침 없음).

### 2-6. 명단에서 객실 배정 · 골프 조 편성 (Min 2026-11-11 「명단에서 객실 배정이나 골프 조 편성도 가능하게」)

팀 상세의 「명단 · 객실 배정 · 골프 조」(배차 아래·메모 위, 기본 펼침). 사람마다 객실·조 두 칸.

- **객실**: 방 = 객실 수 칸(트윈·트리플·싱글)대로 `T1·T2…/R1…/S1…`(`SZCore.partnerRoomSlots`, 순서 트윈 → 트리플 → 싱글). 화면 라벨은 언어별(트윈1·ツイン1·Twin 1), 호텔 제출 명단은 일본어.
- **조**: 4명 1조, 조 수 = 올림(인원÷4), 인원은 고르게(5=3·2 · 6=3·3 · 9=3·3·3 · 10=4·3·3). 조 번호를 하나 더 고를 수 있어(조 수+1) 조를 늘릴 수 있다.
- **지정 먼저, 나머지는 자동**(`SZCore.partnerRooming`·`partnerGolfGroups`): 사람이 고른 칸만 「지정」으로 저장하고, 지정하지 않은 사람은 **명단 순으로 빈 자리**에 넣는다 → 한 사람만 옮겨도 나머지가 맞춰진다. 「자동」을 다시 고르면 해제, [전부 자동으로]=전원 해제.
- **막지 않고 알린다**: 정원을 넘긴 지정(트윈에 3명·조 5명)은 칩이 빨강 + 목록 주황 「객실 정원 초과」「조 5명 이상」. 객실 수가 인원보다 적어 못 들어간 사람은 「객실 없는 사람 N명」(객실 수≠인원 빨강과 같이 뜬다).
- **묶음(party)**: 조는 묶음 전체 명단으로 짠다(5명+1명 → 3·3). 번호는 묶음 안에서 같은 번호 = 같은 조, 지정은 각 팀 행에 저장. 객실은 팀별(객실 수가 팀별이라).
- **저장** = `partner_ops.assign` jsonb `{room:{명단 id:방 키}, grp:{명단 id:조 번호}}`(SQL 167) — 지정한 사람만. 자동 결과는 저장하지 않는다(명단·객실 수가 바뀌면 다시 계산). 명단에서 빠진 사람의 id 는 다음 저장 때 지운다. 초안 → [저장] 모델 그대로.
- **쓰는 곳**: ① 호텔 제출용 명단 xlsx — 「部屋」 열(2번째), 같은 방끼리 붙여 방 순서로(No. 다시 매김). 방이 하나뿐이거나 전부 싱글이 아닌데 자동 배정인 사람이 있으면 내려받을 때 「객실 배정이 자동(명단 순)인 사람 N명 — 보내기 전에 확인」 ② 名簿 인쇄 — 部屋·組 열 + 「部屋割り」「組合せ（ゴルフ）」 묶음(영문명, 조 순서 = 티타임 순서) ③ 월간 가동 현황 골프장 조 수 = 실제 조 편성(묶음은 한 번만 센다, 명단 없는 팀은 올림(인원÷4)).
- SQL 167 전 = 명단 순 자동 배정만 보이고(인쇄·xlsx 에도 나옴) 고르는 칸은 잠김.
- **하지 않은 것**: 라운드(날짜)마다 다른 조 편성 · 라운딩 불참자 · 묶음 팀 사이의 방 합치기 — 필요하면 `docs/future-work.md`.

## 7. 엠클릭 수기 입력표(LGC 수배서 목록 → 엠클릭 등록용, Min 2026-11-05)

- **왜**: 타 여행사 예약은 현지 담당 회사(LGC)의 수배서 목록에만 있고 엠클릭에는 없다. 메리트투어가 엠클릭에 수기로 등록해야 step1 → 수배 목록으로 흘러온다. Min 「엠클릭에다가 수기로 예약 잡아야 하는데 우리가 보기 편한 방식으로」 → LGC 목록을 **엠클릭 예약리스트 열 순서**(구분·대표고객·출발일자·도착일자·기간·요일·출발지·항공·룸타입·상품명·예약·판매금액·비고·현지 비고·항공 비고)로 다시 적은 작업표를 세션에서 만들어 전달(파일은 저장소 밖 §3-2 — 여행사명·일정·요금 포함).
- **열 규칙**: 왼쪽 = 엠클릭 열(「(제안)」 열은 LGC 원문을 읽어 만든 값) / 오른쪽 회색 = LGC 원문(번호·여행사·상품·담당·호텔·골프장·체크 3종). 상품명 제안은 엠클릭 기존 규칙 「여행사 [N박 N+1일] 구마모토 시내 호텔 + 3색 골프 (항공)」(메리트는 「여행사」 접두 없음). **비고 제안은 수배 목록 자동 채움이 읽는 형식 그대로**(「여행사: ○○ / 호텔: ○○ 트윈2·싱글1 / 골프장: 11/16 ○○, ○○ / 싱글룸 N」) — 이 비고를 엠클릭에 그대로 넣으면 등록 뒤 호텔·객실·골프·여행사가 자동으로 채워진다. 티타임·호텔/골프 메모는 현지 비고 제안으로.
- **상태 열**: 입력 필요 / 가확보·가예약·인원 미정(구분 「견적」 제안) / 엠클릭 등록됨 #행사번호(우리 DB 와 날짜·인원 일치 — 여행사 표기가 다르면 메모) / 2건 합산(LGC 한 줄 = 우리 예약 둘) / 메리트투어 · DB 날짜·인원 다름 / DB 미등록 달 / 지난 예약 / 취소 / 시내 상품 아님(송영만·미팅·시찰·골프만) / 메모 행(예약 아님).
- **원문 보정**: 2027.1〜3 시트의 날짜는 파일 연도가 2026 → 시트 이름으로 보정 · 전각 숫자 → 반각 · 인원 「16+1(가이드)」 = 16 + 부기 · 등록표에 없는 호텔·골프장(히고 선밸리·아소 그랑비리오·츠카사 로열·규슈 CC 쇼다이산·기쿠치·아카미즈·다마나·벳셀 호텔)은 「등록표 외」 메모 → 필요하면 기본 설정에서 등록.
- **요금 참고 열**: 요금표 2종(新料金 공통 · 12/17〜3/1 HS/메리트)의 단가로 1인 금액을 다시 계산(12/1 이전 체류는 없음). 시트 2 = 그 단가를 ops 요금표 양식(기간 × 종류)으로 + 패키지 합계 대조(파일 합계 ≠ 재계산인 곳 = 파일 더하기 오류 2건: 新料金 4박5일 트윈·HS 2박3일 호텔 3일분).
- 재생성: 다음 달 LGC 시트가 오면 같은 변환으로 다시 만든다(step1 로 그 달을 등록해 두면 「엠클릭 등록됨」 대조가 그 달까지 된다).
- **Min 결정(2026-11-05)**: 입력표는 쓰지 않고 한국어 번역판을 보며 엠클릭에 직접 등록한다. 요청이 다시 오면 위 변환을 그대로 쓴다.
