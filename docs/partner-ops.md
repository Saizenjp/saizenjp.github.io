## 2. 요금표(新料金 2026.12 · 日別 料金表) → 규칙

- 1인 요금 = **밤마다 호텔**(객실 종류 × 밤 구분) + **라운드마다 골프**(날 구분) + **引率**(밤마다 1일분 + 귀국일분) + 호텔 가산(아마넥·타우 류) + 1인 가산.
- **밤 구분**: 금·토·일·祝日·祝前日 밤 = 휴일 요금 / 그 외 평일 — 현지 日別 料金表 365일(2026-11~2027-10)과 대조해 전부 일치(`SZCore.partnerNightType`).
- **골프 구분**: 토 / 일·祝日 / 그 외(금요일 포함 평일) (`SZCore.partnerGolfType`).
- 파일의 4泊5日(월~금) 싱글·3泊4日(금~월) 싱글·트윈 합계는 이 식과 1円까지 일치했다. 4泊5日 트윈 합계만 파일 쪽 더하기가 2,000 어긋나 있었다(식의 결과를 믿는다).
- **숫자는 저장소에 없다** — 기본 설정 › 요금표에 담당자가 넣는다. 테스트는 가상 요금으로 식만 고정.
- **기간별·대상별 요금표(2026-11-03, Min 「호텔·골프장·송영 각각 · 기간마다 · 2~3월 평일/주말, 그 안에 또 다를 수 있고」)**: SQL 161 `partner_rates` 1행 = 종류(hotel/golf/transfer/guide) × 대상(호텔·코스·차량 id, null=공통) × 기간(from/to, null=상시) → `prices` jsonb. 화면은 「기간」 묶음(이름·시작~종료)마다 호텔별·코스별·차량별 칸을 한 번에 편집([이 기간 저장]·[이 기간 복사]). 해석(`SZCore.partnerPrice`) = 대상 지정 > 공통 · 좁은 기간 > 넓은 기간 · 칸 단위 폴백 → 「2~3월」 위에 「2/10~2/14」를 토요일 골프 칸만 적어 두면 그 칸만 바뀐다. 옛 `partner_settings.rates`(공통 한 벌)는 행이 없을 때 폴백.
- **송영**은 저장된 배차의 (날짜·차량)마다 1대·1일 요금을 팀 단위로 더한다(1인 요금 밖). 요금 행이 없어도 「요금 없음」으로 치지 않는다(引率에 포함되는 상품이 보통).
- **호텔 블록 사용/사용 안 함**(`partner_ops.use_block`, 기본 true): 끄면 그 팀 객실은 블록 띠·블록 초과·검수 ㉓에서 빠진다(별도 예약·블록 외).
- 싱글: 블록이 없으므로 싱글 객실이 있으면 요금(팀 입력 또는 요금표 싱글 단가)이 꼭 있어야 한다 → 없으면 「싱글 요금 미정」 빨강 + 검수 짝 `partner_single_norate`.

## 2-1. 엠클릭 비고로 자동 채움 · 송영 규칙 · 저장 버튼 (Min 2026-11-03)

- **비고 양식(권장)**: `여행사: ○○ / 워싱턴 / 싱글룸 2 / 골프장: 그랜드챔피언, 추오, 그린힐` — 날짜는 `11/5 추오`·`2일차 추오`·`둘째날 추오`처럼 코스 이름 앞에. 순서·구분자는 자유(한 줄에 섞여 있어도 읽는다).
- **읽는 규칙**(`SZCore.partnerRemarkPlan`, step1 적재와 화면 「비고대로 채우기」가 같은 함수): 호텔=등록표 이름·별칭이 처음 나오는 것 / 객실=「싱글룸 N」(단위 없는 수도)·전원 싱글·이름 나열·홀수 1명 + 「트리플 N」 → 나머지 2명씩 트윈, 남는 1명은 싱글 / 골프장=적힌 순서대로 날짜별 1라운드(날짜 없으면 이어서 하루씩 — 코스 수가 박수보다 적으면 도착 다음 날부터, 같거나 많으면 도착일부터, 추정 날짜는 화면에 「날짜는 추정(확인)」) / 여행사=`partnerAgency`.
- **별칭**(SQL 162 `partner_hotels/courses.aliases`, 기본 설정 「별칭」 열): 「추오/츄오/중앙」「그린힐」「미나미아소」처럼 Min 이 쓰는 표기를 쉼표로. 긴 별칭이 우선(「미나미아소트라이얼」 안의 「아소트라이얼」은 안 잡힌다). 영문 별칭은 단어 경계(restaurant 안의 tau 오탐 방지).
- **언제 채우나**: step1 적재 직후 **수배 행이 없는 새 팀만** 자동(호텔·객실 수·담당 기본값·골프 줄 `auto`·`auto_sig`). 이미 수배 행이 있는 팀은 건드리지 않고, 비고가 바뀌면 목록에 「비고 변경됨」 — 담당자가 [비고대로 채우기]를 눌러 초안으로 받은 뒤 [저장]. 툴바 [비고대로 일괄 채우기(N)]은 수배 행이 없는 팀만 한 번에(바로 저장).
- **송영 차량**(`SZCore.partnerVehiclePlan`): 20명 미만 = 하이에스(정원 9)를 등록 순서로 채움(8명=1대·12명=2대·19명=3대), 20명 이상 = 마이크로버스(정원 큰 차) 먼저, 모자라면 하이에스. 배차 제안은 구간마다 차량 수만큼 줄(비고 「1/2대 · 9명」).
- **송영 구간**(`SZCore.partnerLegPlan`, 공항·호텔·골프장 서로 50분 `PARTNER_TRAVEL_MIN`): 도착일=공항→호텔 / 그날 골프면 공항→골프장(도착+115분 안에 티오프면 호텔 경유) · 중간일=호텔→골프장(티 −60)·골프장→호텔 · 귀국일=호텔→공항(출발편 −120) / 그날 골프면 골프장→공항. 저장 행은 출발·경유·도착 지점(SQL 162 `from_pt/via_pt/to_pt`, 없으면 `leg` 로 해석)으로 표기·인쇄(配車表 「空港→ホテル→ゴルフ場」).
- **저장 버튼**(Min 「그냥 수정이 되게 되어 있어서 위험함」): 팀 상세의 모든 입력(호텔·객실·골프 줄·배차 줄·체크·메모·[비고대로]·제안 추가)은 **초안**에만 쌓이고 [저장]을 눌러야 DB 에 쓴다([취소]=버림, 다른 팀으로 이동·월 이동·창 닫기 전에 확인). 날짜별 배차 표와 기본 설정 등록표도 줄을 고친 뒤 [저장(N)]. 요금표는 이미 [이 기간 저장].
- **담당자**: 타츠마루·카이야(2026-11-03 등록, 세 번째는 추후).

## 5. 참고 파일 3종(2026-11-04 수령 — 「계속 참고」, 시내 투어·트라이얼)

파일 자체는 세션 폴더에서만 읽고 저장소엔 두지 않는다(§3-2 — 요금 숫자·고객명 포함). 여기엔 **구조·규칙·대조 결과만**.

- **① 「新料金 2026.12月」(요금표 2026-12~)**: 패키지표 4종(4泊5日 月〜金 · 3泊4日 金〜月 × シングル/ツイン, 朝食込み) — 1人単位로 요일 열마다 ホテル·ゴルフ·引率, 귀국일 열엔 引率만(= 우리 `guide` day/last 와 같은 꼴) + 合計 + 備考(2バック 평일/토일공휴일 요금) + 호텔 메모(アマネク ツイン·シングル 가산, ホテルタウ 가산, 東横イン 없음). 둘째 시트 **「料金表」= 일별 365일(2026-11-01~2027-10-31)** ツイン/シングル 단가·区分(平日/休日/祝日)·공휴일 목록.
  - 우리 모델 대응: `partner_rates`(hotel twin/single × wk/hi · golf wk/sat/sun · guide day/last) + `partner_hotels.surcharge`(아마넥·타우 가산) ✓. **2バック 는 모델에 없음** → 팀 상세 「1인 가산」(price_adj) 수기.
