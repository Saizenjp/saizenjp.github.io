Architecture · 何で作られているか

インストール不要 — ブラウザ + クラウド

🖥 画面(Web)

  • GitHub Pages 上の Webページ — URLを開くだけ
  • PC・ノート・タブレット・スマホ どのブラウザでも動作
  • 画面は 韓・日・英 3言語切替

☁ データ(Supabase)

  • 全データを クラウドDBで保存・共有
  • 複数端末が 同じデータをリアルタイムで参照
  • 自動バックアップ(有料プラン)

🔐 ログイン・権限

  • アカウントで ログイン後に利用(招待発行)
  • 役割・担当 エリア別に表示画面を制限
  • 誰がいつ変更したか 変更履歴を記録

要点: 専用ソフトの導入・サーバ運用が不要。 インターネットとブラウザさえあれば、現場のどの端末からでも同じシステムに接続して共同作業できます。

Sheet03 / 16
STEP 1 · データ登録 (step1)

Excelアップロード一度で その月の全体を構成

アップロードするもの

  • 予約リスト — チーム(行事)マスター
  • 同行者予約 — 個人名簿 + 個人ごとの航空情報(出・帰国便・時刻)
  • 会員グループコード — 会員参照表(初期化しても保持)

自動で行われること

  • チーム・個人・航空・会員判定・等級を自動整理
  • グループコード自動計算(会員=事前割当 / 一般=Fプール)
  • 月単位の同期 — その月のみ更新、他月に影響なし

※ ファイルに無いチームは確認のうえ整理、ファイルにあるチームは割当を保持したまま更新します。

STEP 2 · 部屋割り (room)

個人単位の自動割当 + 現場ルール内蔵

自動割当

  • 会員 → デラックス優先、一般 → 予約種別(ツイン/コンパクト)
  • 清掃効率のための 泊数 → 階ルール(同じ階にまとめる)
  • 月またぎ・定員超過の防止、競合チェックボタン

運用の利便

  • カード/タイムライン表示 · 日付・宿泊施設フィルタ
  • 分割滞在(✂) · 早期退室 · 客室の期間閉鎖
  • 空室クリックで割当 · 取消の巻き戻し · 変更履歴

宿泊: ゴルフテル · 館内別荘 · 蘇母/阿蘇別荘 · ドームハウス · くじゅうヒルズ · 間路ホテル · 志津の宿。

STEP 5 · 注文 — POS + チームQR (pos)

お客様のQR一度 → 正確なチーム・正確な請求

① 注文QRカード
印刷物でチーム別に発行
→
② お客様が撮影
チェックイン時にスマホ保存
→
③ POSでスキャン
スタッフがカメラで読取 → チーム自動選択
→
④ 注文
チーム共通 / 特定1名 / 割り勘

なぜQRか

  • 韓国のお客様 ↔ 日本のスタッフの 言葉の壁を回避
  • 部屋番号の言い間違いなく 正確なチームを特定
  • QRが無ければタグコード・代表者で 検索 →「このチームで合っていますか？」確認

注文 = 精算・厨房へ

  • 注文時の 個人分割が最も正確(誰が頼んだかその場で記録)
  • 請求は 精算へ、調理は 厨房チケットへ自動
  • お客様確認画面(タブレット)にリアルタイム表示

STEP 7·8 · 精算 (settle) / B2B精算 (settle_merit)

ふたつの精算は分離 — 混同しない

現地精算(お客様請求)

  • チーム・個人の 請求書(folio) — 個人分割をまとめて表示
  • POSの注文・支払を リアルタイム反映
  • 御請求書(明細)出力 · 支払方法の記録

B2B精算(会社間)

  • メリットツアー ↔ SaiZen の 事前契約金額
  • 宿泊費(人数×泊数×単価)+ 送迎費を自動計算
  • 現場の追加料金とは 別システム

Security · 権限・セキュリティ (admin)

見えるものも、変えられるものも、人ごとに

役割 + エリア

  • 役割: マスター · マネージャー · スタッフ
  • 担当 エリア(部屋割り・精算・POS・厨房・印刷…)のみ表示

  • 金額・個人情報のテーブルは 権限者のみ読み書き
  • 全ての変更に 担当者・時刻を記録
