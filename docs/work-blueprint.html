1 기능 추가 · 도메인 로직

9홀 추가 → 프론트 매점 POS SQL 34

골프샵은 판매상품 전용 → 라운딩 성격의 9홀 추가는 프론트 매점(venue=front)에 배치. category=라운딩·단가 0(직접 입력).

회원 판정 = 3컬럼 OR(회원 우선) core

고객등급(T) 단독 → 고객등급·회원권구분·회원구분 셋 중 하나라도 회원이면 회원. 초기 등록 오류로 어긋난 케이스 대비. room·pos 적용, 원본 데이터 불변.

夕食 팀 제외(병합) + 분배 정합성 SQL 35

「팀별 태그·인원 수정」에 제외/복원 → 한 팀 지우고 다른 팀에 인원 취합. 원래 합계=수정 후 합계 ✓/⚠ 배너. 항공커버 미영향.

방배정 양식 내보내기: 예약번호→행사번호 fix

내부키 event_seq가 나가던 것을 화면과 동일한 행사번호(event_no)로. 재업로드 매칭은 태그코드 기반이라 영향 없음.

レストラン名札 印刷 = /app/ 완전 동일 양식 fix

간결판 → A4 가로 1팀1페이지(좌우 동일 텐트), 대표자名 길이별 자동크기+님·영문명·태그코드. 입국일 기준.

메뉴 관리 정비

장소별 보기 안을 라인(▸ 서브헤더)으로 재구분. 중복된 「라인별 보기」 토글 제거 → 장소별 단일 보기.

식음 '저녁 식사' 준비중 카드 제거 — 인쇄물 그룹의 「석식 오더」가 식수·명단을 이미 처리하므로 중복 카드 정리.

2 신규 — 재고 · 내부 관리 (1단계)

F&B · 객실 공용 재고 페이지 신규 SQL 36

inventory.html — 부서 토글, 품목·현재고·적정재고·부족 알림, ＋입고/－사용/실사 입출고(원장 기록), 최근 이력.

범용 재고 모델

inv_items(현재고)+inv_txns(입출고 원장). dept로 F&B·객실 한 모델. RLS 읽기=로그인 / 쓰기=kitchen·room. 랜딩 카드 2종.

방향성 — "현장의 모든 수량을 시스템화" 1단계. 다음: 입출고 인라인 입력 · POS 판매 시 자동 차감 연결 · 골프 장비/프론트 매점으로 확장.

3 엔지니어링 성숙도 (CI · 테스트 · 공유 모듈)

테스트 부재·단일파일 중복이라는 최대 부채를 가장 싸게 메우는 1단계.

GitHub Actions CI 신규

.github/workflows/ci.yml — 모든 push/PR에서 문법검사+단위테스트. 깨진 코드의 main(=프로덕션) 진입 차단. 의존성 0.

공유 도메인 모듈 신규

saizen-core.js(UMD) — 회원 판정·날짜 파싱(엑셀직렬·한국어·MDY)·체류 겹침을 단일 진실원으로. room·pos·step1·dinner·dispatch·settle 위임.

검사·테스트

scripts/check-syntax.mjs(전 HTML 인라인 vm 파싱) + tests/*.mjs(node:test, 9건). npm run verify.

이식 키트 — docs/maturity-kit.md: 14hills·메리트투어 등 다른 저장소에 붙여넣어 같은 CI+모듈을 설치하는 paste-ready 프롬프트.

4 인쇄 · UX 개선
