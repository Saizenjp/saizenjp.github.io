## 2. 순서 — 누가 먼저 좋은 방을 받나

1. **회원 짝을 전 팀에 걸쳐 먼저 배정**하고, 그다음 일반 짝을 배정한다.
   회원이 아니면 애초에 먼저 예약할 수 없으므로 회원 예약이 우선이다.
2. 각 패스 안에서는 **예약번호(event_seq) 빠른 순**. 같은 날 예약이라도 초 단위로 번호가 갈리므로
   번호가 빠른 팀이 등급에서 우선한다.
3. 같은 층·같은 등급 안에서는 **높은 층 우선**, 3층이 맨 뒤(기피층).

## 3. 팀 안에서 짝 짓기

- **회원끼리 먼저 묶는다.** 일반은 디럭스에 들어가지 않는다.
- 회원이 홀수로 남으면 **그 1명만** 동행 일반 1명과 디럭스를 같이 쓴다.
  (예: 회원3 + 일반1 → 디럭스 2실)
- 동행 일반도 없이 회원 1명만 남으면(회원 1명 팀, 회원 3명 팀의 세 번째) 그 1명은 **싱글 방**으로 보낸다(§5). 싱글이 없으면 보류(수기).
- 홀수로 남는 일반 1명은 **싱글 방**으로 보낸다(§5).

## 4. 객실 등급 순서

**회원 짝**
```
규칙 층 디럭스 → 다른 층 디럭스 → 스탠다드 트윈 → 컴팩트트윈
```
룸레벨이 층보다 우선한다. 디럭스가 다른 층에 있으면 층을 옮겨서라도 디럭스를 준다.

**일반 짝**
```
스탠다드 트윈 → 컴팩트트윈 → 더블 → (회원 배정 후) 남은 디럭스
```
- 위 순서는 **같은 층 안에서의 순서**다. 일반 짝은 층을 먼저 고르고(규칙 층 → 나머지 높은 층, §7) 그 층 안에서 스탠다드 트윈 → 컴팩트 순으로 채운다.
  회원 짝이 디럭스를 못 받아 내려갈 때만 반대로 **타입이 먼저**다(전 층의 스탠다드 트윈을 다 본 뒤 컴팩트).
- 일반은 **원칙적으로 디럭스에 들어가지 않는다.** 회원 짝을 전 팀에 걸쳐 먼저 배정하므로,
  일반 차례에 남아 있는 디럭스는 **회원이 다 쓰고 남은 방**이다. 그 방까지 비워둔 채
  일반 팀을 미배정으로 남기지 않는다. (Min 2026-08)
- ~~더블(7층 2실)~~ 은 2026-09-15 Min 결정으로 **싱글로 재등록**했다(1709·1712, 정원 1). 코드의 더블 폴백은 남아 있지만 해당 방이 없다.

**홀수 1명**
```
규칙 층 싱글 → 5층 싱글 → 다른 층 싱글 → 없으면 보류(수기)
```
- 야마나미 호텔은 싱글이 다 차도 **트윈에 1명을 넣지 않는다**(침대 하나를 버리는 판단은 사람이 방을 보고 정한다 — Min 2026-08).
- **싱글 객실이 아예 없는 숙소(간지호텔·쿠주힐즈·돔하우스)** 만 2인실을 1명이 단독으로 쓴다. 이때 다른 팀이 이미 든 방에는 넣지 않는다(빈 방이 없으면 보류).

## 6. 3층은 한 급 아래

```
3층 디럭스  → 트윈으로 계산
3층 트윈    → 컴팩트트윈으로 계산
3층에 컴팩트트윈이라는 객실은 없다
```
그래서 **실질 디럭스는 38실이 아니라 34실**이다.

## 7. 박수 → 층 (청소팀 가동 효율)

**이 규칙이 존재하는 이유는 객실 청소팀 때문이다.** 같은 층을 같은 박수(=같은 퇴실일)로 맞추면
그 층이 한날 통째로 비므로 청소팀이 층 단위로 한 번에 움직인다. 층 안에 퇴실일이 섞이면
같은 층을 며칠에 걸쳐 몇 번씩 오가야 해서 인원이 훨씬 많이 든다.

```
3박 · 4박  →  9층, 6층, 3층
7박        →  11층, 10층, 7층, 4층
그 외 박수  →  12층, 8층, 5층
```

> ⚠ **이건 우선순위이지 제한이 아니다.**
> 규칙 층이 다 찼는데 다른 층이 비어 있으면 **그 층을 쓴다.**
> 층 규칙 때문에 미배정이 생겨서는 안 된다. (Min 2026-08)
>
> 청소 효율은 **가능한 한** 지키는 목표이지, 손님을 못 받는 이유가 될 수는 없다.

구현: 풀을 규칙 층 먼저 → 나머지 층(높은 층 순)으로 **정렬만** 한다. 걸러내지 않는다.
같은 층 묶기(2방 이상 팀)도 규칙 층에서 먼저 찾고, 안 되면 다른 층에서 찾는다.

**싱글 객실의 층 순서(Min 2026-09)** — 싱글(정원 1)은 3·4·5·6·7층에만 있다(각 4실 = 등록 20실. 3층 1309 는 연중 사용 불가라 **객실 잠금(`room_inventory.active=false`)** 으로 보유에서 빠지고(활성 19), 1312 는 `room_closures` 기간 폐쇄라 실사용 18실 — 폐쇄는 자동배정이 날짜별로 빼고, 일별 체류 현황표는 폐쇄 수를 칸의 검은 숫자에 더해 보유(활성 수)를 고정한다. **원칙(Min 2026-10-02): 연중 안 쓰는 방 = 잠금, 기간이 있는 것 = 폐쇄 등록.**
8층 이상의 싱글은 소형트윈=컴팩트트윈으로 개조됐고, 7층 1709·1712 는 2026-09-15 더블에서 싱글로 바꿨다). 위 규칙 층 중 싱글이 있는 층을 먼저 쓰고,
그다음이 **5층(넘칠 때 쓰는 층)**, 그다음 나머지 층(높은 층 순)이다.
```
7박        →  7층, 4층  → 5층 → 6층, 3층
3박 · 4박  →  6층, 3층  → 5층 → 7층, 4층
그 외 박수  →  5층       → 7층, 6층, 4층, 3층
```
구현: 규칙 층 순서 뒤에 5층을 붙인 뒤(`singleFloorOrder`) 같은 정렬을 쓴다. 전원 싱글·이름 지정 싱글(§9 `singleRemark`)과
홀수 잔여 1명(§4) 모두 이 순서다.

## 8. 항상 지키는 것

- **정원 초과 불가** — DB 트리거(`rooms_capacity_guard`)가 겹치는 날짜의 점유 합을 잠그고 막는다.
- **기간 폐쇄된 방**(`room_closures`)은 자동배정에서 제외.
- **수기 배정은 건드리지 않는다** — 자동배정 재실행은 `assign_source='auto'` 만 정리한다.
- **다른 달 배정도 본다** — 정원 체크는 로드된 달이 아니라 DB 전체 점유 기준.

## 9. 자동배정은 자동으로 돈다

- **엠클릭 룸타입 열(2027~, SQL 163 `bookings.room_type`, Min 2026-11-03 「3번은 그렇게 다 설정되어 있는거야」)**: 비고에 싱글 언급이 없을 때 룸타입을 본다 — 「싱글」=전원 1인 1실(아래 전원 싱글과 같은 조건: 호텔동 + 체류 내내 빈 싱글이 인원수만큼 있을 때만, 아니면 보류) / 「싱글,트윈」=홀수 팀은 남는 1명이 싱글(평소 규칙), 짝수 팀은 누가 싱글인지 비고에 없으면 보류(수기 — 4명이면 싱글 2+트윈 1이지만 누구인지 모른다). 미배정 카드에 룸타입 배지. 일별 체류 현황의 싱글 신청도 같은 수를 더해 센다. **입국일(dep_date) 2027-01-01 이후 예약에만**(`SZCore.roomTypeOn` · SQL 163 `ROOMTYPE_FROM` — Min 2026-11-03 「2026년 예약은 그대로 조건 건드리지말고 해. 2027년부터야」): 2026 입국 예약은 step1 이 room_type 을 저장하지 않고(null) 화면·서버 자동채움도 입국일로 한 번 더 거른다 → 2026 규칙 불변.

월을 불러온 뒤 **미배정이 남아 있으면 자동배정이 바로 한 번 실행**된다(Min 2026-08 — 버튼을 누르지 않아도).
수기·분할 배정은 건드리지 않고 `assign_source='auto'` 만 정리하므로 반복 실행해도 안전하다.

한 번에 미배정을 최소화하도록 기본값을 켜뒀다.

| 스위치 | 기본 | 뜻 |

| `allowSingle` | **켬** | 싱글 객실이 **없는 숙소**(간지·쿠주·돔하우스)에서 홀수 1명이 2인실을 단독 사용. 야마나미 호텔은 싱글이 다 차면 트윈으로 내리지 않고 보류(§4) |
| `splitOdd` | 켬 | 홀수 잔여 분리(현재는 기본 동작) |
| `singleRemark` | **끔** | 비고에 「싱글」이라 적힌 팀 중 **「전원 싱글」·「싱글룸: 이름」처럼 확실한 건만 자동**(2026-09) — 야마나미 호텔동에서 **싱글 객실이 체류 내내 인원수만큼 비어 있을 때만** 그 사람들을 1인 1실, 나머지는 평소대로 짝. 모자라면 팀 전체 보류(트윈에 1명을 넣지 않는다). 「싱글룸 2개」처럼 누구인지 없는 요청·체류 일부·「문의·미정·마감·매진」처럼 정해지지 않은 말이 붙은 요청·간지/쿠주(싱글 타입 없음)는 보류 → 수기. 「싱글룸 없음·사용 안 함」(요청이 아님)과 「싱글룸 대기·불가·만실·취소·보류」(확정되지 않은 요청 — Min 2026-08 「취소성 언급 제외」)는 싱글 요청이 없는 팀처럼 **평소대로 둘씩** 넣는다(싱글이 확정되면 사람이 옮긴다). 「문의·미정·마감」과 외래어·일본어 표기(캔슬·웨이팅·キャンセル 등)는 **싱글이 적힌 구절 안에서만** 본다(「전원 싱글룸 / 석식 문의」는 전원 싱글 — 2026-11 검수 29차). ⚠ 「대기·불가·만실·취소·보류」 다섯 낱말은 아직 **비고 전체**에서 찾는다 — 「전원 싱글룸 / 석식 취소」처럼 다른 항목의 취소에도 걸려 그 팀이 평소대로 둘씩 배정된다(Min 결정 대기 — 권장: 싱글이 적힌 구절에서만 찾고, 걸리면 보류). 싱글차지는 자동 기록 없음. 켜면 싱글 언급을 무시하고 둘씩 묶는다 |

## 10. 그래도 남는 미배정

자동으로 못 채우면 **「⚠ 미배정 N건 사유」** 에 사유별로 모인다(사유 칩·숙소 칩·검색).
팀 카드를 누르면 그 팀의 배정 창이 바로 열리고, 방은 사람이 정한다.
조치를 체크해 다시 돌리던 **[이 방법으로 재배정]** 은 2026-08 에 없앴다 — 남은 선택지가
「비고에 싱글이라 적힌 팀도 둘씩 묶기」 하나뿐이었고, 그건 사람이 방을 보고 정할 일이다.

| 사유 | 조치 |
|---|---|
| 홀수 잔여 1명(싱글 만실) | 수기 — 트윈을 혼자 쓰게 할지 사람이 정한다(야마나미 호텔) |
| 싱글 요청(누구인지 불명·체류 일부·문의/미정/마감·싱글 부족) | 수기 |
| **빈 방 없음(전 층)** | **자동 불가** — 날짜·숙소를 바꾸거나 수기 |

## 11. 아소별장(8인 1동) — 호텔 배정 뒤에 옮긴다

자동배정 대상이 아니다. **먼저 전원을 호텔에 배정한 뒤**, 조건이 맞는 팀만 옮긴다.

```
추천 조건 = 팀 묶음 합계 또는 한 팀 인원이 딱 8명
```

- 묶음은 **手配書 팀 묶기**(`print_overrides.team_group`) 기준이다.
- 5~7명도 물리적으로는 들어가지만 **추천하지 않는다**. 필요하면 현장에서 수기로 옮긴다. (Min 2026-08)
- 「아소별장」 칩을 켜면 객실 목록 위에 후보가 뜨고, [아소별장으로 이동]이 기존 배정을 풀고 다시 배정한다(되돌리기 있음).
- 이미 배정된 팀 칩에는 **「아소 가능」** 뱃지가 붙는다.

## 12. 아직 안 정한 것

- **트리플 3실**을 3명 팀에 자동으로 쓸지 — 현재는 수기.
  (3명 팀은 지금 2명 트윈 + 1명 싱글로 자동 처리된다.)
- **3·4박의 디럭스 8실 제약** — 3층 강등 때문에 3·4박 회원이 몰리면 디럭스가 부족하다.
  「회원 연간 디럭스 0회」가 실제로 발생하는지는 방배정 통계 ②·⑤에서 확인한다.

## 12. 쿠주힐즈 → 쿠쥬 프라이빗 타운 2027 (Min 확정 2026-10-07)

- **명칭**: 2027년부터 「쿠쥬 프라이빗 타운」. 메리트투어 안내(`merittour.github.io/2027`)는 이미 바뀌었고, **사이젠 시스템(DB 숙소 키 `쿠주힐즈`·코드의 상품명 판정·단가·숙소 순서)은 2026 예약이 끝난 뒤 한 번에 바꾼다**.

- **2027 소보별장 명칭(Min 2026-11-03)**: 소보 5호(4인 1동)=「소보 테라스」, 소보별장 2·3호 트윈=「히노키 스테이」. 자동배정은 상품명대로 간다(소보 테라스=5호 통째·히노키 스테이=2·3호). 객실 마스터의 이름(소보 N호)은 쿠쥬와 같은 시점(2026 예약 종료 후)에 바꾼다.
