## 0. 작업 원칙 (반드시 지킬 것)

1. **구현 전에 설계 확인.** 각 Phase 시작 시 변경할 파일·SQL·화면을 요약해 Min에게 먼저 보여주고 승인 후 구현한다. 아래 「결정 필요」 항목은 임의로 정하지 말고 질문한다.
2. **CLAUDE.md 규칙 준수.** 특히
   - CSS는 변수만(`var(--accent)`), HEX 폴백 금지
   - UUID에 `parseInt()` 금지
   - 한국어·일본어 문자열 검색은 `grep` 대신 Python3 `re`
   - 화면 문구는 기존 `tx()` 사전 방식으로 ko/ja/en 3언어 모두 추가 (현장 UI 기본은 일본어)
   - 문서가 코드보다 앞서지 않게 한다(구현한 것만 문서화)
3. **SQL 마이그레이션은 `156_` 부터** 번호순, 멱등(`if not exists`, `do $$ … $$`), 파일 머리에 배경·주의 주석. 마지막 파일은 `155_guest_outings.sql`.
4. **정산 기록은 절대 물리 삭제하지 않는다.** 지금처럼 `voided` 소프트 취소만 쓴다. 새 테이블도 같은 원칙.
5. **검증:** 수정한 HTML/JS는 `node --check`(스크립트 추출) + jsdom 스모크, 화면은 Playwright headless. SQL은 `00_VERIFY.sql` 에 확인 쿼리를 추가한다.
6. 금액은 엔 정수. 소수점 연산 결과는 아래 단수처리 규칙으로만 정수화한다.

## P0. 정리

1. 실DB 스키마를 읽어(`information_schema`, `pg_constraint`) `docs/` 에 현재 정산 스키마 스냅샷을 남긴다.
2. `09_settlement_core.sql` 을 고치지 말고(이미 실행된 이력), **`156_settlement_schema_sync.sql`** 에 실DB 기준을 명시하는 주석·멱등 구문만 둔다. folios→bookings FK는 **다시 만들지 않는다**(워크인 event_seq 대역 때문에 일부러 없는 상태 — 유지).

4. `README.md` 를 현재 구조(화면 35개, SQL 155+, edge-functions)로 갱신.

## P1. 세율 구분

### 스키마 (`157_tax_rate.sql`)
- `menu_items.tax_rate smallint not null default 10` — 허용값 `10, 8, 0`
- `charges.tax_rate smallint not null default 10` — 청구 시점의 세율을 **복사 저장**(메뉴 세율이 나중에 바뀌어도 과거 청구는 불변)
- `charges.tax_class text not null default 'taxable'` — `taxable`(과세) / `exempt`(비과세) / `outside`(불과세: 골프장 이용세·입탕세 등)
- 기존 행 backfill: 전부 `10`, `taxable`
- check 제약으로 조합 검증(`outside`/`exempt` 이면 tax_rate=0)

### 계산 규칙
- 단가는 지금처럼 税込(内税).
- **세액은 청구서(folio) 단위·세율별로 1회 단수처리**한다(적격청구서 요건). 행별 세액 합산 방식은 쓰지 않는다.
  - 세율별 税込合計 × rate/(100+rate) → 단수처리
  - `charges.tax` 컬럼은 참고값(행별 추정)으로만 남기고, 표시·출력은 세율별 집계값을 쓴다.
- 단수처리 방식(버림/반올림/올림) → **결정 필요 D1**

### 화면
- `menu.html`: 메뉴별 세율 선택(10%/8%/비과세). 기본 10%.
- `pos.html`: 담을 때 메뉴의 세율을 charges 로 복사. 8% 품목은 행에 `※` 표시.
- `settle.html` 수기 청구 추가: 세율 선택 칸 추가(기본 10%).
- 8% 대상 품목 지정 → **결정 필요 D2** (메뉴 데이터 입력은 현장 몫, 기능만 제공)

## P2. 적격청구서 표기

### 설정값
- 발행자 정보 저장소: 기존 설정 테이블이 있으면 사용, 없으면 `158_org_settings.sql` 로 `org_settings(key text primary key, value text, updated_at, updated_by)` 생성. RLS: 읽기 authenticated, 쓰기 admin 영역만.
- 키: `invoice_reg_no`(T+13자리), `issuer_name_ja`, `issuer_address_ja`, `issuer_tel`
- `admin.html` 에 편집 카드 추가. 등록번호 형식 검증 `^T\d{13}$`.
- 등록번호 값 → **결정 필요 D3**

### 영수증·御請求書 출력 (`openReceipt()` 및 御請求書 인쇄)
필수 표기:
1. 발행자명 + 등록번호
2. 거래 연월일
3. 거래 내용 (8% 대상은 `※` + 하단에 「※は軽減税率(8%)対象」)
4. **세율별 税込合計**와 **세율별 消費税額**
5. 불과세 항목(이용세 등)은 별도 줄 「(不課税)」 로 소계에서 분리
- 한국어로 인쇄할 때도 위 항목의 일본어 표기는 함께 남긴다(기존 「領収書」 병기 방식과 동일).
- 宛名 미기재 허용(적격간이청구서) — 현행 유지.

## P3. 일일 마감 (レジ締め)

### 스키마 (`159_daily_closings.sql`)
```
daily_closings (
  id uuid pk default gen_random_uuid(),
  biz_date date not null,
  outlet text not null,            -- front / restaurant / golf / all (단위는 D4)
  cash_expected integer not null,  -- 시스템 집계(그날 현금 payments, voided 제외)
  cash_counted integer,            -- 실사
  card_expected integer not null,
  card_terminal integer,           -- 단말기 일계표 금액(수기)
  diff_note text,                  -- 차액 사유(차액≠0 이면 필수)
  status text not null default 'draft',  -- draft / closed / reopened
  closed_by text, closed_at timestamptz,
  reopened_by text, reopened_at timestamptz, reopen_reason text,
  created_at timestamptz default now(),
  unique (biz_date, outlet)
)
```
- 영업일 기준 시각(예: 04:00 경계) → **결정 필요 D5**

### 잠금
- `closed` 인 영업일·매장에 속하는 `charges`/`payments` 의 insert·update(voided 변경 포함)를 **트리거로 거부**.
- 해제는 admin 영역만 `reopened` 로 전환 + 사유 필수, `audit_log` 에 기록.
- 마감 후 발견된 오류는 **다음 영업일에 정정 청구(마이너스 행)** 로 처리하는 것을 기본 흐름으로 안내.

### 화면
- 신규 `hub/closing.html` (index.html 「프런트·판매」 그룹에 카드 추가, area 키 `closing`, `user_access` 에 등록)
- 구성: 날짜·매장 선택 → 시스템 집계(현금/카드, 세율별 매출, 카테고리별 매출, 취소 건수·금액) → 실사 입력 → 차액 표시 → 마감
- 일보 인쇄(A4 1장, 일본어 우선) + Excel(ExcelJS 4.3.0)

## P4. 골프장 이용세 장부

- 1차는 **장부(집계)만** 만든다. 손님 청구서에 부과할지는 → **결정 필요 D6** (메리트 패키지는 B2B 단가에 포함됐을 가능성)
- 플레이 인원 원천: 그날 `golf_groups` 의 조원 + `walkins`(holes 있는 것). 간지호텔 평일 팀처럼 야마나미에서 라운딩하지 않은 팀은 제외(코스 배정표와 같은 규칙 재사용).
- 비과세 판정: `passengers.birth` 로 연령 자동 판정(18세 미만·70세 이상 후보), 그 외 사유(장애인 등)는 화면에서 수동 지정 + 증빙 메모.
- 세액 단가·비과세 범위·9홀 취급 → **결정 필요 D7** (설정값으로 둘 것, 하드코딩 금지)
- 스키마(`160_golf_tax.sql`): `golf_tax_exemptions(play_date, person_key, reason, note, created_by)` 정도로 최소화. 집계는 뷰/RPC.
- 출력: 일별·월별 「利用人員・課税人員・非課税人員(사유별)・税額」 표, Excel.

## P5. 회계용 월 출력

- `settle.html` 매출 출력 옆에 「会計用CSV」 추가.
- 행 단위: 영업일 × 부문(source) × 세율 × 결제수단 → 税込額·消費税額
- 대상 회계 소프트·열 형식 → **결정 필요 D8**. 확정 전에는 위 행 단위의 범용 CSV(UTF-8 BOM)만 만든다.

## P6. 장애 대비

- 인쇄용 「手書き伝票」 양식(일자·매장·팀코드·품목·세율·금액·결제수단) 1장을 `notice.html` 또는 closing.html 에서 출력.
- 복구 후 입력: settle 수기 청구에 「事後入力」 체크 → `charged_at` 을 과거 시각으로 지정 허용, note 에 자동 표기. 마감된 날짜에는 P3 잠금이 우선.
