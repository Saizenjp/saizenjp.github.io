# 마샬 Ai(테크노크래프트) 플레이어 파일 내보내기 — 코스 배정표

코스 배정표(`ops/hub/course.html`) 툴바의 **[⬇ 마샬 Ai 명단]** 이 그날 조편성을 테크노크래프트 「フロント系システム IF 仕様 v6.0.2」 2-1 プレーヤ情報 형식으로 내려받는다.
IC Green(호텔 시스템)에서 수작업으로 넣던 명단을 ops 에서 바로 만들어 마샬 기지 PC 의 공유 폴더에 두면 된다.

- 테크노크래프트 회신(2026-09·2026-10-26): 「자사 시스템에서 만든 csv/txt 를 테크노가 읽어가는 방식」 = 이 파일.
- 사양서(PDF)·IC Green 표본 파일(2026-08-27)은 **저장소에 두지 않는다**(제3자 문서·명단 PII, §3-2). 아래는 거기서 뽑은 규칙만.

## 파일
| 항목 | 값 |
|---|---|
| 파일명 | `YYYYMMDDhhmmssPlayerFile.csv`(내려받는 시각, 표본과 동일) |
| 문자코드 | Shift-JIS(CP932) — 페이지 안 `cp932Bytes` 인코더 |
| 줄끝 | CRLF · 머리글 없음 · 0바이트 파일은 만들지 않는다 |
| 단위 | **한 조(카트) = 한 줄 19칸**. 조원이 있는 조만. 카트 번호 없는 조는 **파일에서 뺀다**(①은 필수·0 금지) |

## 칸(19)
| # | 칸 | 값 |
|---|---|---|
| ① | カート番号 | `golf_groups.cart_no` 숫자만 |
| ②③④ ×4 | コンペ番号 · プレーヤ番号 · 氏名 | ② **행사번호**(手配書 묶음은 그날 보드에 있는 대표팀 행사번호 → 대표가 없으면 묶음 안 최소 행사번호). 같은 번호 = 마샬이 한 컴페(리더보드)로 집계 · ③ 그날 고정 번호(`marshal_player_no`, SQL 127, 따옴표) · ④ `"영문명-태그코드[순번]"`(KimOkJu 형식, 태그 영문2+가나1, 가타카나는 반각, 묶음이면 手配書 순번 1·2…). 4명 미만이면 나머지 자리는 빈칸 3개 |
| ⑤⑥ | 캐디 번호·이름 | 빈칸 |
| ⑦ | スコア入力種別 | 0 |
| ⑧ | スタート予定コース | `MR_COURSE` = 아소 0 · 소보 1 · 쿠주 2 (Min 결정 2026-10-27 — 코스 미정이면 빈칸) |
| ⑨ | スタート予定時間 | hhmm, 앞 0 없이(06:57 → 657) |
| ⑩ | コンペ名 | 태그코드(순번 없이) |

⑪ 이후(조합 카트·핸디캡·GlidNo·생년월일·운용일·작성일시·로커·속성·성별)는 省略可 라 내지 않는다(IC Green 표본도 ⑩까지).

## IC Green 표본과 다른 점(의도)
- 표본은 같은 카트 줄이 2~15번 반복돼 있다(IC Green 출력 버릇). 사양이 「같은 카트 번호가 여러 줄이면 뒤 줄 채택」이라 무해하고, 우리는 한 줄만 낸다.
- 표본의 카트 `999`는 IC Green 의 「미배정」 자리표. 우리는 그런 줄을 내지 않고 화면에서 번호를 채우게 한다(카트 번호 배분).
- 당일 손님(워크인)은 명단(이름)이 없어 파일에 들어가지 않는다.

## 코스 번호
- **⑧ 코스 번호 = 아소 0 · 소보 1 · 쿠주 2**(Min 결정 2026-10-27 「이렇게 가정하고 진행」). 표본은 0·1·2 세 값을 쓰는 것만 보여 준다. 마샬 기지 PC(運行管理)의 코스 설정과 다르다고 밝혀지면 `course.html` 의 `MR_COURSE` 한 줄만 바꾼다.

## 검증
- 단위: scratch `t-marshal.cjs`(표본 1행과 바이트 단위 동일 모양·따옴표 위치·묶음 번호·제외 규칙·CP932).
- 테크노크래프트 쪽 실제 읽기 확인은 현장에서 한 번 해 본다(파일을 공유 폴더에 두고 30초 뒤 카트 화면에 이름이 뜨는지).
